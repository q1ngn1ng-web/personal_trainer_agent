# 01 · 资料来源与知识导入：竞品调研、差异与技术选型

> 对应环节：用户选择训练资料来源 → AI 生成训练路径
> 文档状态：**初稿，竞品部分未经实测**
> 证据状态：本文所有竞品结论分为 `【公开信息】` / `【推测】` / `【已实测】` 三档，当前以 `【公开信息】` 与 `【推测】` 为主

---

## 一、结论先行

三句话：

1. **资料来源不是差异化点，是入场券。** NotebookLM、Quizlet、Dify 都能把用户资料变成可用的学习或问答内容，这一块拼的是"能不能用"，不拼"有没有"。
2. **真正的差异在"资料之后"**：资料 → 训练项 → 排期 → 评测 → 达标判定 → 复盘，这条闭环目前只有 Quizlet（仅卡片）和 Anki（仅复习）各自覆盖一段，没有产品从头做到尾。
3. **技术选型上，第一版不该上向量库。** 个人场景的资料规模（一本书 = 几百个切片）用 SQLite FTS5 就够；上 embedding 会引入阈值校准、缓存、成本三类新问题，而它解决的问题当前还不存在。

## 二、同类产品怎么做的

### 2.1 通用 RAG 平台（Dify / RAGFlow / FastGPT）

| 维度 | 做法 |
|---|---|
| 资料来源 | 文件上传、网页抓取、API 同步、Notion/飞书等连接器 |
| 解析 | 内置多种解析器，可选 OCR、表格抽取；RAGFlow 主打深度文档理解 |
| 切片 | 提供模板（通用 / 问答对 / 表格），可调分块大小与重叠 |
| 检索 | 向量检索 + 关键词混合 + 重排模型，多数支持混合权重配置 |
| 面向谁 | **开发者**，需要自己配置整条链路 |

`【公开信息】` 三家都在做"让开发者快速搭 RAG"，切片与检索参数对用户是暴露的。
`【推测】` 默认参数面向通用场景，对"教材/手册"这类强结构文档并没有做针对性优化。

**对我们的启示**：这套东西是"给开发者搭问答机器人"的，不是"给学习者做训练"的。我们可以借鉴它的解析与检索设计，但目标不同——它要回答准确率，我们要"练到会"。

### 2.2 AI 学习/研究工具（NotebookLM / ChatGPT 学习模式 / Khanmigo）

| 产品 | 资料怎么进 | 产出什么 | 引用 |
|---|---|---|---|
| NotebookLM | 上传 PDF / 网页 / 音视频 / Google Docs | 问答、学习指南、测验题、思维导图、音频概览 | **每句回答可回指到原文片段，点击跳转** |
| ChatGPT（学习模式/项目） | 上传文件到项目上下文 | 讲解、追问式引导 | 弱，依赖模型复述 |
| Khanmigo | 平台自带课程内容 | 苏格拉底式追问、逐步引导 | 不适用（内容自持） |

`【公开信息】` NotebookLM 的"引用回指"是它最被称道的特性；它也能生成测验。
`【推测】` NotebookLM 生成的测验是**一次性产物**，没有排期、没有复习调度、没有达标判定——它回答"这里有什么"，不负责"你学会没有"。

**对我们的启示**：NotebookLM 已经证明"资料 → 引用锚定 → 生成练习"这条路可行，是我们要参考的对象。但它止步于"生成一份东西给你"，剩下"每天都练、练到会"的部分是空的。

### 2.3 记忆与刷题工具（Anki / Quizlet / SuperMemo）

| 产品 | 资料怎么进 | 训练闭环 | 自适应 |
|---|---|---|---|
| Anki | 用户自己制卡（或插件导入） | 有复习调度，无内容生成 | `【公开信息】` 用户自行设定「New cards/day」与「Maximum reviews/day」两项限额，系统只负责按间隔调度（来源：docs.ankiweb.net/deck-options.html，2026-09-19 抓取） |
| Quizlet | 用户建学习集或导入，也有官方内容 | Learn / Test / Match 多种模式 | 按掌握度推进，有目标日期选项 |
| SuperMemo | 自建材料 | 间隔重复鼻祖 | `【公开信息】` SM-2 算法：第 n 次复习间隔 `I(n) = I(n-1) × EF`，其中 EF 为难度因子且不低于 1.3（来源：super-memory.com/english/ol/sm2.htm，1990 年原始论文，2026-09-19 抓取） |

`【公开信息】` Quizlet 的 Learn 模式会根据答对答错调整出题顺序与频次。
`【推测】` 这三个产品的共同前提是**用户已经知道自己要背什么**——它们解决"记住"，不解决"从一门模糊的目标到知道该背什么"。

**对我们的启示**：我们的上游（把"我想学虚拟语气"拆成训练项）和下游（达标判定）正好是它们不覆盖的部分。

### 2.4 应试与课程类（松鼠AI / Coursera / 得到）

| 产品 | 资料来源 | 交付形态 |
|---|---|---|
| 松鼠AI | 平台自持知识图谱 | 诊断 → 路径 → 按掌握度推进 |
| Coursera / edX | 讲师提供的固定课程 | 固定周数、固定作业 |
| 得到 / 混沌 | 平台自制课程 | 固定节数音频课 |

`【公开信息】` 松鼠AI 主打"先诊断再规划路径"。
`【推测】` 它们都不让用户提供资料，因为内容是平台的资产与壁垒。

**对我们的启示**："不让用户选资料"是商业课程产品的必然选择，不是最优学习设计。个人学习者的资料天然散落（教材、讲义、自己的笔记），所以"让用户带资料进来"对我们是刚需，对课程平台不是。

## 三、共性规律（五条）

1. **平台型把内容当资产，所以不开放资料；工具型把资料当输入，所以必须开放。** 我们属于后者。
2. **解析 → 切片 → 索引是标准三步**，没有产品跳过它。
3. **引用回指是信任的关键**，NotebookLM 把它做成了口碑点；多数工具做得很弱。
4. **资料与训练项是脱节的**：要么只有资料问答（NotebookLM），要么只有训练项（Anki），中间那一步"从资料里长出训练项并绑定来源"普遍缺失。
5. **资料更新后普遍要求重建**，没有产品做"增量重建 + 影响面提示"（哪些训练项受影响、要不要重练）。

## 四、我们的差异与优势

### 4.1 差异点（可以讲、但要讲得准）

| 维度 | 同类普遍做法 | 我们的做法 | 强弱判断 |
|---|---|---|---|
| 资料入口 | 上传即用，与后续无关 | 资料进 `sources` 表，**每个训练项回指 `source_id`** | 中（NotebookLM 已有引用） |
| 资料 → 训练项 | 生成一次性练习 | 一条资料产出**多形态训练项**（背诵 / 改错 / 复述 / 辨析）并进入排期 | **强** |
| 资料与验收标准 | 无关联 | 资料决定 `acceptance` 是否可测（教材自带习题 → 可用正确率） | **强** |
| 闭环长度 | 生成即结束 | 生成 → 排期 → 评测 → 调度 → 达标 → 复盘 | **最强** |
| 资料变更 | 重建索引 | 增量重建 + 影响面提示 | 中（实现难度不低） |

### 4.2 一句话定位（面试用）

> NotebookLM 回答"这份资料里写了什么"，Anki 解决"记住了没有"，我做的两件事是它们之间的那段：
> **把资料拆成训练项、绑上来源、排进计划，再用评测结果决定下一次练什么。**

### 4.3 不要这么说（会被反驳）

- ❌「我做了一个 RAG 学习助手」——面试官会立刻问"和 NotebookLM 有什么区别"
- ❌「我的优势是引用可追溯」——NotebookLM 已经做到了，且做得比个人项目好
- ❌「我支持 PDF / Word / Excel 导入」——这是功能罗列，不是优势

## 五、技术选型

### 5.1 文档解析

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| MinerU / 专业解析服务 | 对复杂版式、公式、表格处理好 | 依赖重、慢、需部署 | **采用**（已有 `PythonProject16` 的实战经验可复用） |
| PyMuPDF / pdfplumber | 轻量、快、无外部依赖 | 版式复杂时结构丢失 | 备选（简单 PDF 走这条路） |
| 直接让 LLM 读 PDF | 实现最快 | 长文档超上下文、成本高、不可控 | 否 |

**为什么这样选**：解析质量决定后面一切。`PythonProject16` 里踩过的坑（图片信息丢失、版式错乱）在这里会以同样方式出现。

### 5.2 切片策略

| 方案 | 结论 |
|---|---|
| 按标题层级 + 段落边界切 | **采用**——教材/讲义的结构本身就是语义边界 |
| 固定字数切 | 否——会把一个知识点劈成两半 |
| 语义切片（embedding 判断边界） | 暂不——引入模型依赖，收益未验证 |

### 5.3 检索：要不要上向量库（**最关键的一条**）

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| SQLite FTS5（全文检索） | 零新增依赖、可解释、可单测 | 只能匹配字面，同义表达查不到 | **第一版采用** |
| 混合检索（FTS5 + embedding） | 覆盖率更高 | 引入阈值校准、缓存、成本、模型依赖 | 暂缓 |
| 专业向量库（Milvus/pgvector） | 规模大时必要 | 部署与运维成本，个人场景用不上 | 暂缓 |

**判断依据**：ADR-0002 写的重评估触发条件是「出现跨资料检索、相似题推荐或海量资料匹配需求」。
个人自用场景下，一个训练的资料来源通常是 1-3 份，切片量在数百级——**这个规模 FTS5 完全够用，触发条件尚未满足。**

这不是"不会用向量库"，而是"知道什么时候不该用"。

### 5.4 存储与引用

- `sources` 表：`id` / `type`（ai_generated / user_upload / user_paste）/ `title` / `origin`（文件名或 URL）/ `imported_at` / `checksum`
- `source_chunks` 表：`id` / `source_id` / `ordinal` / `text` / `heading_path`
- 训练项表增加 `source_chunk_ids`，实现"训练项 → 原文"的回指
- `checksum` 用于增量重建：内容没变就不重跑解析

## 六、为什么这样做（设计原则）

1. **LLM 只做语义，规则做状态**（ADR-0001）。解析、切片、索引、排期都是确定性的，不该交给模型。
2. **先解决"有没有"，再解决"准不准"**。没有评测集之前调检索参数是无依据调优；先让链路跑通并留下证据。
3. **来源必须可追溯**，否则"信任源"只是口号——用户点一下能跳回原文，信任才成立。
4. **不做一次性产物**。同类产品生成完就结束，我们生成的每一样东西都要进入状态机，能被排期、被评测、被归档。

## 七、面试追问预案

**Q：这和 NotebookLM 有什么区别？**
> NotebookLM 做的是"读资料 + 生成引用"，它止步于给你一份东西。我做的是把这份东西变成有排期、有评测、有达标判定的训练闭环。举个具体差别：NotebookLM 生成 10 道题，答完就结束了；我的系统会记录你哪几道错、错在哪个知识点，然后把那部分排到明天的复习里，连续达标后自动降频。

**Q：为什么不上向量库？**
> 三个理由：一是我现在的资料规模是数百个切片，FTS5 完全够；二是上向量库要引入阈值校准、缓存和成本三类新问题；三是我在 ADR 里写明了触发条件——出现跨资料检索或相似题推荐时再上，现在没到。我更愿意把时间花在评测集上，因为"检索准不准"这件事我现在还无法证明。

**Q：用户传一本 400 页的书，你怎么保证不跑偏？**
> 三步：解析时保留标题层级，切片按结构走；训练项生成时强制回指原文切片，界面上能点回去核对；验收标准与资料绑定，如果资料里没有对应练习，我会把验收标准降级为可观察的质性判据，而不是编一个数字。

**Q：资料中途换了怎么办？**
> 现在的设计是增量重建加影响面提示。`checksum` 判断内容是否变过，变了才重跑解析；同时列出受影响的训练项，让用户决定是保留旧训练、还是重练。

## 九、本次联网调研的可复现记录

**调研时间**：2026-09-19
**方法**：`curl` 直连官方文档站，保存原文后按关键词提取

### 已核实（可直接引用）

| 结论 | 来源 | 抓取结果 |
|---|---|---|
| Anki 的每日数量限额由**用户自己设定**（New cards/day、Maximum reviews/day），系统只负责按间隔调度 | `https://docs.ankiweb.net/deck-options.html` | 60,253 字节，含 "New Cards/Day"、"Maximum Reviews/Day" 等章节 |
| SM-2 算法：`I(n) = I(n-1) × EF`，EF 下限 1.3 | `https://www.super-memory.com/english/ol/sm2.htm` | 9,868 字节，含公式原文与 "E-Factors should not fall below the value of 1.3" |

### 未能核实（保持推测）

| 结论 | 原因 |
|---|---|
| NotebookLM 的引用回指与测验生成形态 | `support.google.com` 连接超时 |
| Quizlet Learn 模式的掌握度调整机制 | Cloudflare 拦截 |
| Dify 的切片参数与混合检索配置项 | 文档站为单页应用，未抓到正文 |
| RAGFlow 的深度文档解析能力细节 | 域名解析失败 |

### 结论怎么用

- 表格里标 `【公开信息】` 并带 URL 的两条，面试时可以直接讲。
- 其余仍为 `【推测】`，讲的时候要主动说"这是我从外部行为推断的，没有实测"。
- **要升级成 `【已实测】`，只能自己动手**：NotebookLM 与 Quizlet 需要你在本机浏览器里试用并截图（见第八节待验证清单）。
