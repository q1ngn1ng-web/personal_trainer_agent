# adaptive-practice-composition · 自适应练习编排（backlog，面试后实施）

> 状态：**仅提案，未实施**（用户决策 2026-11-16：先登记构想，面试前不动主链）。
> 来源：用户复述第 1 课练习时描述的期望形态与现实现的差距——原话是「每次训练从上次抽巩固题、抽错题，再加入新题；题库渐进式生成；首轮部分覆盖、逐轮补全；用户可提前训练」。审计判定的行动：**与其面试时讲不存在的能力，不如把它登记成真实的 backlog**。

## Why

当前排期模型（ADR-0021）是**确定性五轮**：路径生成时一次确定全部训练项，每轮覆盖全部训练项，每轮每题懒生成**全新题**，到期才能练、前序轮未完成不出下一轮。这个设计的优点是可复现、可测试、心智简单；但三个体验缺口真实存在：

1. **错题不回流到日常训练**：错题只通过「连续 2 次通过才达标」「测验失败补练第 6 轮」「深度解析看历史」三条间接路径起作用——日常第 N 轮训练里**不会**出现「这道题你上次错了，再来一遍」；
2. **不能提前练**：今天状态好想多练几轮，系统不允许（today 只显示到期且前序未完成的最早一轮）；
3. **同题重练缺失**：巩固的本质是「同一道题隔几天再练」，而当前每轮都是新题——考的是知识点，不是题本身；间隔复习的「再认」环节偏弱。

## What Changes（构思，实施前需逐项设计决策）

- **会话内混合编排**：日常训练的当日清单按「新题为主 + 近期错题回炉（带上限，如 ≤2 道）+ 快到冷却期的巩固题（可选）」组成；错题优先级来自 `practice_attempts.mistake_reasons` 与连续未通过次数（数据已全量落库，10-31 起可用）。
- **提前训练（显式动作）**：任务卡增加「提前练下一轮」入口——**只提前产生作答机会，不改原定 due_date 与锚定排期**（累计顺延与历史轨迹语义保持不变）；提前完成的轮次在到期日不再出现。需决策：提前练是否计入「连续 2 次通过」的达标口径（建议：计入，作答记录不分提前/到期）。
- **同题重练（巩固题）**：把冷却期外的原题（question_bank 已有全量登记）以低概率混入日常清单——与测验的变式优先策略形成「日常原题巩固 + 测验变式检验」的分工。

### 设计张力（实施前必须先决策）

| 构想 | 与现状的冲突 | 处置建议 |
| --- | --- | --- |
| 渐进式覆盖（首轮覆盖 30%…） | 与 ADR-0021「每轮覆盖全部训练项」直接冲突；全覆盖是「确保所有知识点被练到」的现有保证 | **默认不做**。若真要做，等于换排期模型，须新 ADR 取代 0021 并重写 plan_service 五轮生成——成本高收益存疑，仅当用户明确确认再立项 |
| 错题回炉混排 | today 的「每题最早未完成一轮」纯查询语义会被打破（同题可能出现两行：本轮新题 + 回炉旧题） | 回炉题作为**附加行**（kind 或 reason 标 `review_recall`），不动主轮次行 |
| 提前训练 | today 查询条件 `due_date<=今天` 是全系统「今天练什么」的唯一口径 | 显式参数（`include_future=true` 仅该入口生效），查询层最小改动 |

## 非目标（Non-goals）

- **面试前不实施**（用户决策 2026-11-16）；不影响判分、达标、测验任何规则
- 不做自适应间隔（SM-2 拟合）——固定 +1/3/7/15/30 维持
- 不做「渐进式覆盖」除非用户确认更换排期模型（见张力表）
