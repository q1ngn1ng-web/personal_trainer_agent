# org-and-roles · 任务清单

> 按依赖顺序编号。每个任务写明验收方式。认证选型见 ADR-0014，未落盘视为未完成。

## 1. 数据层

- [ ] 1.1 新增 `organizations` / `users` / `memberships` 三张表
  - 验收：`init-db` 后三张表可查看，`memberships.role` 只接受 `admin` / `employee`
- [ ] 1.2 新增 `assignments` / `assignment_targets` / `assignment_receipts` 三张表
  - 验收：`assignments.status` 只接受 `draft` / `published` / `archived`
- [ ] 1.3 既有表补 `org_id`（`trainings` / `training_paths` / `training_items` / `sources` 等）
  - 验收：每张业务表均含 `org_id`，写入时自动填充
- [ ] 1.4 迁移逻辑可重复执行，老数据归入默认组织
  - 验收：对已有 `data/trainer.db` 跑迁移，训练列表条数不变且全部带上默认 `org_id`

## 2. 认证（复用组件，不自研）

- [ ] 2.1 接入认证组件并封装成适配层（业务代码不直接依赖具体组件）
  - 验收：登录、登出、会话过期三个场景可手动跑通
- [ ] 2.2 密码仅存哈希；初始化管理员通过 CLI 完成
  - 验收：数据库中查不到明文密码；`uv run python -m src.cli create-admin` 可用
- [ ] 2.3 登录后把 `user_id` / `org_id` / `role` 注入会话上下文
  - 验收：页面能拿到当前用户的三个字段

## 3. 权限校验（服务层）

- [ ] 3.1 实现统一鉴权入口：校验 `org_id` 与角色，失败抛统一异常
  - 验收：单测覆盖四类越权（员工读他人资料、员工读他人进度、管理员跨组织、员工发布任务）
- [ ] 3.2 所有服务函数入口接入鉴权
  - 验收：代码检查确认无遗漏，越权调用均被拒绝并记日志
- [ ] 3.3 资料可见范围生效：`personal` 仅本人、`org_shared` 限同组织
  - 验收：单测断言跨用户、跨组织均不可读

## 4. 内容层与进度层分离（ADR-0013）

- [ ] 4.1 明确并实现两层写入路径：内容层按组织写入，进度层按人写入
  - 验收：同一份企业公共区资料被两名员工使用时，内容只解析一次（日志可验证）
- [ ] 4.2 经验难度按人统计，支持按标签聚合，样本量低于 5 人时回退结构难度
  - 验收：单测构造 3 人与 6 人两组，断言前者回退、后者使用聚合值

## 5. 培训任务

- [ ] 5.1 任务创建与发布：四要素（资料范围 / 验收标准 / 目标人群 / 截止日期）缺一不可
  - 验收：缺任一要素时发布被拒并提示
- [ ] 5.2 目标人群匹配：按 `all` / `tag` / `user` 三种方式命中成员
  - 验收：发布前展示命中人数；不在人群内的员工无法接收
- [ ] 5.3 员工接收任务：创建个人训练，目的字段标记 `assigned`
  - 验收：接收后训练归属正确，且只能被该员工看到
- [ ] 5.4 员工调整个人投入参数，不改变任务给定的验收标准与必修范围
  - 验收：单测断言调整后 `acceptance` 与必修项数量不变
- [ ] 5.5 覆盖模式下节奏调整不影响覆盖范围
  - 验收：模拟连续超时，断言总题量与必修覆盖不变

## 6. UI

- [ ] 6.1 登录页与角色分流：`admin` 进管理端，`employee` 进员工端
  - 验收：两种角色登录后看到的导航不同
- [ ] 6.2 员工端只展示三样：待办、我的进度、我的资料
  - 验收：页面不存在查看他人进度的入口
- [ ] 6.3 管理端：资料库（含企业公共区）、任务、人员、报表
  - 验收：四个入口均可打开并完成对应操作
- [ ] 6.4 刻意不做：员工之间互看与排行榜
  - 验收：代码检查确认无相关接口与入口

## 7. 企业价值指标

- [ ] 7.1 首次达标周期：记录 `first_passed_at`，按人中位数聚合
  - 验收：构造数据跑通口径，结果可复算
- [ ] 7.2 必修覆盖率与首次通过率：按固定口径实现
  - 验收：单测覆盖边界（无人接收、全部完成、部分完成）
- [ ] 7.3 报表展示口径说明
  - 验收：每项指标旁能看到口径与统计时段
