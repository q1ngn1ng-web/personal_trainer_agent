# org-and-roles · 组织、角色与培训任务

> **状态：已后置（2026-09-20）**。本 change 保持提案状态，**暂不进入 apply**，规格保留备用。
> 依据：`workspace/decisions/ADR-0019-个人版优先企业版后置同一条代码线.md`。
> 个人版仍会预留 `org_id` 与 `scope` 字段（填默认值），但**不实现鉴权与角色**。
> 将来启用时，本 proposal 的规格可直接复用。

## Why

到目前为止所有设计都是**单人视角**：资料、路径、训练记录都属于同一个人。

但产品定位是面向企业——管理层的诉求是"把培训资料发下去，知道谁练了、谁达标了"，员工的诉求是"我知道该练什么、练到哪了"。

没有组织与角色，就没有"企业公共区"这种分发关系，**培训周期与达标率也无从量化**。而这两个指标正是 toB 场景最需要拿出来的效果证据。

## What Changes

- 新增**组织与成员**：`organizations` / `users` / `memberships`（含角色）
- 新增**两种角色**：`admin`（管理层：上传、发布、看报表）、`employee`（员工：接收培训、练自己的）
- 新增**资料可见范围**：`org_shared`（企业公共区）/ `personal`（个人资料），落地 `training-source-selection` 预留的 `org_id` 与 `scope`
- 新增**培训任务**：管理层选择资料范围 + 验收标准 + 目标人群 + 截止日期并发布，员工接收后开始训练
- 员工接收任务后，目的字段由任务填充（来源标记 `assigned`），员工补充个人化的投入参数
- 新增**企业价值指标**：首次达标周期、必修覆盖率、首次通过率
- 执行 ADR-0013：**内容层按组织存一份，进度层按人存**
- 沿用 ADR-0001：权限与状态判定由规则层执行，不由 LLM 判断

### 关键取舍

| 选择 | 备选方案 | 放弃理由 |
|---|---|---|
| **组织维度一开始就写入所有表** | 先做单组织，以后再迁移 | 引入组织后，资料、路径、训练记录、达标数据全都要带 `org_id`；**数据隔离是事后最难补的一类改动**，预留成本远低于迁移 |
| **复用成熟认证组件** | 自研密码与会话管理 | 自研容易被问穿（密码怎么存、会话怎么管、能否越权）；精力应放在权限模型与业务逻辑（见 ADR-0014） |
| **第一版只有两种角色** | 细粒度权限（按单份资料、按字段授权） | 没有真实需求支撑的权限模型是过度设计；两种角色已能跑通"分发 → 接收 → 看报表"闭环 |
| **做"培训任务"而不只是共享文件夹** | 只做企业公共区 | 没有验收标准与截止日期，就算不出达标率与周期；**任务是把资料变成可量化培训的最小单位** |
| 指标按"人"统计，不按"次" | 统计训练次数 | 业务方关心"多少人达标、多久达标"，不是练习次数 |

详见 `workspace/decisions/ADR-0013-内容层与进度层分离一次加工多人复用.md` 与
`workspace/decisions/ADR-0014-认证复用成熟组件第一版只做两种角色.md`。

## 非目标（Non-goals）

- 不做 SSO / LDAP / 企业微信 / 钉钉对接（第一版用邮箱密码）
- 不做跨组织协作与组织加盟
- 不做细粒度权限（按单份资料授权、字段级权限）
- 不做合规级审计日志（只保留可排查问题的操作记录）
- 不做与考勤、薪酬、绩效等 HR 系统的对接
- **不做部门层级的组织树**（第一版只有"组织"一层，人群用标签分组）
- 不做计费、套餐、试用期等商业化能力
- 不做员工之间的数据互看（员工只看自己，管理层看汇总与明细）

## 留给后续的问题（本次不决）

1. **澄清流程需要扩展"任务派发"入口**：现有 `goal-clarification` 规格假定用户从零描述目标，而任务派发场景下目的由任务给定。本 change 只在规格里写明约束，**不改 `goal-clarification` 的规格**，避免与进行中的 change 冲突
2. **指标按岗位统计**需要岗位字段，第一版用标签分组，是否需要正式岗位模型待定
3. **十要素模板生成的 10 份 md** 留废问题仍未决（延续 `training-path-generation` 的待决项）

## Capabilities

### New Capabilities

- `org-and-roles`: 组织、成员、角色与权限——组织与用户模型、两种角色、资料可见范围、服务层统一鉴权、组织隔离
- `training-assignment`: 培训任务——管理层发布任务、员工接收并生成个人训练、企业价值指标计算

### Modified Capabilities

无。有意不改 `goal-clarification` 与 `trainer-generation`，避免与进行中的 change 产生 delta 冲突。

## Impact

- **代码**：`src/services/`（认证、权限、组织、任务发布与接收、指标计算）、`src/db/`（新增组织与用户相关表 + 既有表补 `org_id`）、`src/ui/`（登录页、管理端、员工端）、`src/cli/`（初始化管理员）
- **数据**：新增 `organizations` / `users` / `memberships` / `assignments` / `assignment_targets` / `assignment_receipts`；既有表补 `org_id`；`data/trainer.db` 不提交 git
- **依赖**：需引入认证组件（选型见 ADR-0014），同步追加到 `requirements.txt`
- **API**：无（仍为 Streamlit；需要开放接口时单独立项）
- **测试**：权限判定矩阵、组织隔离、任务目标人群匹配、指标口径的纯函数单测
- **证据**：首次达标周期、必修覆盖率、首次通过率、题目复用率——**待实测，当前标【待验证】**
