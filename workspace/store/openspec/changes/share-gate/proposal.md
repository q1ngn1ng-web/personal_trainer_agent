# share-gate · 分享门禁与公开导入（私有文档出门前逐件确认 + 开放链接）

> **状态：提案（已拍板待实施）**。用户拍板于 2026-11-22，本文档只做规格，不含实现。
> 依赖：`plan-sharing`（已实施 `e75fc84`——克隆机器、share_links、预览/拉取/推送端点）、
> `content-visibility`（已实施 `325ec89`——训练与资料三档可见性 private/specific/public、
> `training_shares`/`source_shares` 授权表、PUT 可见性端点）。
> 实施时与 `member-invite` 同批（其四项拍板已于 2026-11-22 决议，见该 change tasks）。

## Why

`content-visibility` 落地了"谁能**看到**什么"（三档可见性），`plan-sharing` 落地了
组织内的"计划**导入**"（链接拉取 + 推送副本）。但两个缺口让"个人公开分享"不成立：

1. **公开导入通道缺失**：已实施的 `public` 档 = 组织内公开——一个无组织的个人
   （member-invite 取消自动进组后成为常态）或跨组织的朋友试图打开分享链接，
   会被"非组织成员"拒绝。用户要求：别人（含跨组织）可以导入自己的训练计划与资料。
2. **私有内容无感出门**：现行分享动作（链接生成/推送/可见性设为 public）**不检查**
   计划引用的文档可见性——计划一公开，里面挂着的私有文档（笔记、扫描 PDF）
   跟着被复制出去。用户拍板：**出门前必须逐件盘点确认**，全部确认完才允许分享。

## What Changes

* **开放链接（anyone）**：`share_links.open_level ∈ {org, anyone}`（存量默认 `org`
  行为不变）。`anyone` 链接 = **任何登录用户**可预览并导入（对齐"链接制先行"拍板：
  公开的作用域是链接可达性，不做公共广场列表页）。
* **分享门禁（本期核心）**：四类出向分享动作前置统一门禁——
  ①训练可见性设为 `public`；②生成 `org` 链接；③生成 `anyone` 链接；④推送指定成员。
  门禁规则：**计划引用的每份文档，其可见级必须 ≥ 分享受众级**
  （private < specific < public），不达标文档必须被**逐个勾选确认**（提供全选）后
  定向升级，全部确认完才放行分享动作；缺一份即阻止（409 + 返回缺失清单）。
* **定向升级语义**（确认一份文档 = 把它升到本次分享的受众级）：
  - 训练设 public / org 链接 / anyone 链接 → 文档升 `public`；
  - 推送指定成员 → 文档升 `specific` 并向目标成员授权（已是 public 则达标）。
* **原子性**：确认升级与分享动作在同一事务端点完成——不存在"文档升了级但分享
  没发生"或反向的中间态。
* **导入语义不变**：复用 plan-sharing 克隆机器（独立副本、进度清零、溯源引用、
  题库完整复制、幂等）；预览不泄露题库与参考答案的规则继续生效。

### 关键决策

| 选择 | 备选方案 | 放弃理由 |
| --- | --- | --- |
| 公开导入落在**链接开放级别**（anyone 链接） | 训练加第四档"全站公开" | 已实施 `public`=组织公开，语义已锁定；改语义破坏既有行为；用户拍板本就是"链接制先行" |
| 门禁覆盖**全部四类**出向动作（含组织级） | 仅门禁 anyone/push | 用户原话明确"计划设置公开时也要弹窗逐个确认"；豁免组织级会形成同组织两套口径 |
| 确认即**定向升级**文档可见性 | 只记一次性放行（不改文档权限） | 一次性放行后文档仍私有，下次分享又要确认一遍且受众语义不明；升级是持久、可审计的 |
| `org` 链接待遇 = `public` 档受众 | org 链接豁免门禁 | 组织公开与 org 链接的受众相同（组织成员），文档可见级必须一致才不漏 |

## 非目标（后置，不进本期）

* **部分确认 / 题库裁剪**：未确认文档所派生的题库不随计划分享（题库级裁剪）——
  用户明确"后期再做，现在就做需要全部确认的这一块"；
* 公共广场（公开计划的浏览/搜索/排序列表页）——等有真实公开量再做；
* 独立资料库（资料脱离训练单独分享/导入）——本期资料只随计划；
* 订阅式共享（副本跟随原计划更新）；
* 判分链路任何改动（并行会话负责区域）。

## Impact

* `share_links` 加 `open_level` 列（默认 `org`，存量行为不变）；无其他 schema 变更
  （可见性与授权表已由 content-visibility 落地）。
* 新端点：`POST /api/trainings/{id}/share/gate`（查询缺失清单）与
  `POST /api/trainings/{id}/share/confirm`（事务：定向升级 + 执行分享动作）；
  现有 link/push/PUT-visibility 端点接入门禁校验（未过门禁 → 409 带清单）。
* `pull_by_token` / 预览按 `open_level` 放宽（anyone → 任何登录用户）。
* 前端：分享对话框升级——缺失文档清单 + 逐个勾选 + 全选 + 受众级说明；
  生成链接时的 org/anyone 开关。
