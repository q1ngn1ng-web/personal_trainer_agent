# training-execution-feedback · 设计文档

## Context

### 背景

这一章要补上整条链路最后一段：用户真正在练的时候，系统怎么知道"他是不是真的会了""他是不是觉得太难/太容易"，以及据此怎么调。

现有实现是单向的：用户勾选完成、自评回忆题对错、写三省，系统按回忆题正确率微调。有两个缺口：看不懂主观感受；没有不依赖自评的检验。

### 当前状态

- `daily-execution`：今日任务卡、勾选、三省、回忆题正确率
- `weekly-review`：机械指标 + LLM 校准建议，周日触发
- 评测模块已有 strict / fuzzy 双模式（ADR-0002）
- 难度有四档与依据，运行中按准确率校准（ADR-0010）
- 总题量与单次负荷分离，超时只降负荷（ADR-0011）

### 约束

- 沿用 ADR-0001：LLM 只产出信号与解释，动作由规则层决定
- 沿用 ADR-0010：难度是「题目 × 学习者」的关系
- 沿用 ADR-0011：覆盖模式下不得因难度而跳过必修知识点
- 不做多模态情绪识别

### 利益相关方

- 员工：训练过程中要能一键表达"太难/太容易"，不想填表
- 管理层：需要看到测验通过情况，判断培训是否真的有效
- 用户本人：演示与面试讲解

## Goals / Non-Goals

**Goals:**

- 用户能用一次点击表达主观感受，系统据此调整难度、范围或题量
- 系统不被"感觉良好"带偏：主观信号与客观表现冲突时以客观为主，并把冲突告诉用户
- 有不依赖自评的定期测验，且测验能测出真实理解而非短时记忆
- 达标有明确的三级判据

**Non-Goals:**

- 不做面部、语音等多模态情绪识别
- 不做防作弊
- 不做员工间的比较

## Decisions

### D1 四失信号与动作映射

来源是《学记》的四失：多、寡、易、止。落成四类信号与四类动作：

| 信号 | 用户表达 | 诊断 | 动作方向 | 具体手段 |
|---|---|---|---|---|
| `too_much`（多） | 太多了、记不住 | 贪多嚼不烂 | **收敛** | 减少单次题量、聚焦少数知识点、延长周期 |
| `too_narrow`（寡） | 太窄了、就这些？ | 所知狭窄 | **拓展** | 补充相邻知识点、换角度提问、引入来源中的关联章节 |
| `too_easy`（易） | 太简单、没挑战 | 轻视以为易 | **深挖** | 升一档难度、加变式、要求讲解或复述 |
| `too_hard`（止） | 太难了、想放弃 | 畏难而止 | **鼓励** | 降一档难度、拆小题、给提示、降低单次负荷 |

### D2 采集方式：一键标签，不填表

任务卡上提供四个快捷标签，点击即提交；另有一个可选的自由文本框。

**为什么必须一键**：训练进行中要求用户填评分表，直接会让人放弃使用。标签零成本，愿意多说再写字。

自由文本由 LLM 分类为信号（可多标签），输出结构：

```json
{
  "signals": ["too_hard"],
  "confidence": 0.82,
  "evidence": "用户原话片段"
}
```

**LLM 只做分类，不出动作**（ADR-0001）。

### D3 冲突裁决：主观信号与客观表现不一致时以客观为主

这是本章最重要的一条规则，直接针对"误以为自己懂了"。

| 情况 | 处理 |
|---|---|
| 信号 `too_easy` 且准确率 < 0.6 | **不升难度**，提示「你自评偏容易，但正确率只有 X%，建议先巩固再加深」 |
| 信号 `too_hard` 且准确率 > 0.9 | **不降难度**，提示「正确率其实很高，是不是题量或节奏的问题？」并转向降低单次负荷 |
| 信号与客观表现一致 | 按信号方向调整 |
| 客观数据不足（不足 3 次作答） | 采信主观信号做**轻微**调整（如加提示），不做结构性调整 |

详见 `ADR-0015`。核心立场：**客观表现有数据支撑，主观感受没有；冲突时优先客观，但必须把冲突显式告诉用户**——不是替他决定，而是让他看见自己的偏差。

### D4 防抖动：结构性调整设上限

| 调整类型 | 生效条件 |
|---|---|
| 轻微调整（加提示、拆小题） | 即时生效 |
| 结构性调整（难度升降一档、题量增减、范围拓展） | 同类信号当日累计 2 次，且**每日最多一次** |

覆盖模式下所有调整**不得减少必修知识点覆盖**（ADR-0011）。
每次调整写入 `adjustment_log`：信号、依据、动作、前后值、是否被冲突规则拦截，可追溯可回滚。

### D5 定期测验：三个理由对应三条设计

| 为什么要测验 | 设计回应 |
|---|---|
| 人容易自我催眠，误以为理解了 | 测验题**不取自刚练过的原题**，必须是变式或新题；不给提示 |
| 系统需要持续反馈以保持校准 | 测验结果写入经验难度并触发难度校准与路径调整 |
| 应用所学有助于巩固 | 测验本身进入排期，是一次正经训练，不是额外负担 |

### D6 测验与日常训练的区别

| 维度 | 日常训练 | 定期测验 |
|---|---|---|
| 取题 | 当前薄弱项，可重复练 | **跨知识点抽样**，覆盖本阶段必修项，且避开花刚练过的原题 |
| 提示 | 可有 | 无 |
| 判分 | strict / fuzzy | 同口径但更严：不判「部分正确」，按 `acceptance` 直接判定 |
| 反馈时机 | 即时 | 全部完成后统一给出 |
| 结果用途 | 更新经验难度 | 更新经验难度 + **计入达标判定** + 可能触发回退重练 |

### D7 测验触发条件

三种入口：

1. **阶段末**：某阶段全部必修项达标时自动生成测验
2. **时间兜底**：距上次测验 ≥ 7 天（可配置）
3. **用户手动**：「我现在想验证一下」——**时机可自主，内容不可挑选**

### D8 未通过的处理：回退重练，而不是补考

```
测验未通过的训练项 → 标记为需重练 → 重新排入未来计划
→ 相关知识点进入加强模式（提高出现频率）
→ 达标后重新触发测验（用新题，不用上次的题）
```

**为什么不是补考**：补考只解决"这次没过"，不解决"这个知识点没掌握"。但重考时必须换新题，否则测的是对上次答案的记忆。

### D9 达标判定的三级判据

| 层级 | 判据 |
|---|---|
| 训练项达标 | `acceptance` 判据满足 **且连续 2 次达标**（防偶然） |
| 阶段达标 | 覆盖模式：该阶段全部必修项达标；达成模式：该阶段验收标准满足 |
| 任务达标 | 必修覆盖 100% **且** 最终测验通过 |

连续 2 次的要求是为了过滤"蒙对"——单次达标可能来自运气或提示。

## Risks / Trade-offs

| 风险 | 影响 | 处理方式 |
|---|---|---|
| 信号被滥用（一直点"太简单"） | 难度失控 | 冲突规则拦截 + 每日结构性调整上限 + 调整留痕可回看 |
| 客观数据太少时误判 | 调整方向错误 | 不足 3 次作答时只做轻微调整，不做结构性调整 |
| 测验题与练习过于相似 | 测不出真实理解 | 取题时强制排刚练过的原题，要求变式或新题；人工抽检相似度 |
| 测验增加负担导致放弃 | 使用率下降 | 测验频率受阶段末与 7 天兜底双重控制；测验结果同时计入训练成果，不是额外作业 |
| 回退重练导致计划膨胀 | 覆盖模式下总时长超预算 | 回退项优先占用单次负荷，必要时提示用户延长周期（沿用 ADR-0011） |
| 四失分类被模型误解 | 动作方向错 | 分类结果带置信度与原文依据；低置信度时只做轻微调整 |
| 与 `training-path-generation` 的阶段划分耦合 | 阶段末测验时机错乱 | 测验以"阶段全部必修项达标"为触发条件，不按固定日期 |

## 验收方式

- 单测：冲突裁决四种分支、每日调整上限、测验取题排除刚练过的原题、三级达标判定、覆盖模式下调整不减少必修项
- 手动场景：点「太简单」但正确率低，系统应拒绝升难度并给出提示
- 手动场景：阶段全部达标后自动生成测验，且测验题与刚练过的题不同
- 手动场景：测验未通过后，相关训练项被重新排入计划，且重考使用新题
- 指标：信号分布、测验通过率、调整前后准确率变化——**待实测，当前标【待验证】**
