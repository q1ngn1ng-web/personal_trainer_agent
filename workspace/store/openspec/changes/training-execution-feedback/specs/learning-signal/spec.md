# learning-signal Specification

## ADDED Requirements

### Requirement: 用户能一键提交学习感受

系统 SHALL 在任务卡上提供四个快捷信号标签（`too_easy` / `too_hard` / `too_much` / `too_narrow`）
与一个可选自由文本框。点击标签 SHALL 立即提交，**不得要求用户填写评分表或必填说明**。
信号 MUST 落库并记录所属训练、训练项与提交时间。

#### Scenario: 一键提交信号

- **WHEN** 用户点击「太难了」
- **THEN** 系统立即记录一条 `too_hard` 信号
- **THEN** 不要求用户补充任何说明

#### Scenario: 附带自由文本

- **WHEN** 用户点击标签后另写了说明文字
- **THEN** 原始文字被完整保留，供分类与后续复盘使用

### Requirement: 自由文本必须由 LLM 分类为信号，且只分类不出动作

当用户提交自由文本时，系统 SHALL 调用 LLM 将其分类为四类信号（可多标签），
输出 MUST 包含 `signals`、`confidence` 与引用用户原话的 `evidence`。
LLM MUST NOT 输出任何调整动作或调整幅度，动作 SHALL 由规则层决定。

#### Scenario: 分类结果结构

- **WHEN** 用户提交「这些题我都记住了，太没意思」
- **THEN** 系统得到 `signals` 包含 `too_easy`，并附带置信度与原文依据
- **THEN** 该输出中不包含任何"提升难度"之类的动作指令

#### Scenario: 置信度过低

- **WHEN** 分类置信度低于设定阈值
- **THEN** 系统只允许触发轻微调整，不得触发结构性调整

### Requirement: 信号必须由规则层映射为动作

系统 SHALL 按固定映射把信号转为动作：`too_much` → 收敛（减单次题量、聚焦知识点）；
`too_narrow` → 拓展（补相邻知识点、换角度）；`too_easy` → 深挖（升难度、加变式、要求讲解）；
`too_hard` → 鼓励（降难度、拆小题、给提示、降单次负荷）。
覆盖模式下，任何调整 MUST NOT 减少必修知识点的覆盖范围。

#### Scenario: 信号触发动作

- **WHEN** 用户提交 `too_much` 信号
- **THEN** 系统减少单次训练题量
- **THEN** 必修知识点总数保持不变

#### Scenario: 覆盖模式下不得跳过知识点

- **WHEN** 训练处于覆盖模式且用户持续提交 `too_hard`
- **THEN** 系统降低难度与单次负荷，并提示可延长周期
- **THEN** 系统 MUST NOT 移除任何必修知识点

### Requirement: 主观信号与客观表现冲突时以客观为主

当主观信号与客观表现不一致时，系统 MUST 以客观表现为准决定是否调整，
MUST NOT 直接按用户主观感受执行结构性调整，并且 MUST 把冲突显式提示给用户。

#### Scenario: 自评偏容易但正确率低

- **WHEN** 用户提交 `too_easy` 且该训练项最近准确率低于 0.6
- **THEN** 系统不提升难度
- **THEN** 系统提示自评与正确率的差异，建议先巩固

#### Scenario: 自评偏难但正确率高

- **WHEN** 用户提交 `too_hard` 且该训练项最近准确率高于 0.9
- **THEN** 系统不降低难度
- **THEN** 系统转向提示可能是题量或节奏问题，并优先调整单次负荷

#### Scenario: 客观数据不足

- **WHEN** 该训练项累计作答不足 3 次
- **THEN** 系统只允许轻微调整，不得做结构性调整

### Requirement: 结构性调整必须限频并留痕

系统 SHALL 限制结构性调整的频率：同类信号当日累计达到 2 次才可触发，
且每日结构性调整 MUST NOT 超过 1 次。轻微调整可即时生效。
每次调整 MUST 写入调整日志，包含信号、依据、动作、调整前后取值，以及是否被冲突规则拦截。

#### Scenario: 达到触发条件

- **WHEN** 用户当日第二次提交同一类信号且客观表现一致
- **THEN** 系统执行一次结构性调整并写入调整日志

#### Scenario: 超出每日上限

- **WHEN** 当日已执行过一次结构性调整，用户再次提交同类信号
- **THEN** 系统只记录信号，不再执行结构性调整
- **THEN** 页面提示调整将在次日生效

#### Scenario: 被冲突规则拦截

- **WHEN** 信号与客观表现冲突导致调整被拦截
- **THEN** 调整日志记录该次拦截及原因
