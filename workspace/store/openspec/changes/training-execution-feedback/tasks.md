# training-execution-feedback · 任务清单

> 按依赖顺序编号。每个任务写明验收方式。选型见 ADR-0015 与 ADR-0016。

## 1. 数据层

- [ ] 1.1 新增 `learning_signals` 表（信号类型 / 训练项 / 原文 / 置信度 / 时间）
  - 验收：`init-db` 后表可查看，信号类型只接受四类枚举
- [ ] 1.2 新增 `adjustment_log` 表（信号 / 依据 / 动作 / 调整前后取值 / 是否被拦截及原因）
  - 验收：每次结构性调整都能查到一条完整记录
- [ ] 1.3 新增 `assessments` 与 `assessment_items` 表（测验批次、取题与判分结果）
  - 验收：一次测验能查到其全部题目与各自判分结果
- [ ] 1.4 `daily_logs` 扩展字段：`signal_submitted_at`、`assessment_id`（可空）
  - 验收：迁移可重复执行，老数据不丢

## 2. 信号采集与分类

- [ ] 2.1 UI 提供四个快捷标签 + 可选文本框，点击即提交
  - 验收：点一次标签即落库，不出现必填校验
- [ ] 2.2 新增 LLM 用途 `signal_classify`：自由文本 → `signals` / `confidence` / `evidence`
  - 验收：输出通过 Schema 校验，且**不包含任何动作字段**
- [ ] 2.3 分类失败或置信度低于阈值时只允许轻微调整
  - 验收：单测模拟低置信度，断言不产生结构性调整

## 3. 动作裁定（规则层）

- [ ] 3.1 四类信号的固定动作映射：收敛 / 拓展 / 深挖 / 鼓励
  - 验收：单测覆盖四类信号各自的动作方向
- [ ] 3.2 冲突裁决：`too_easy` + 低准确率 → 不升难度；`too_hard` + 高准确率 → 不降难度
  - 验收：单测覆盖四种冲突分支，并断言给出提示文案
- [ ] 3.3 客观数据不足（<3 次作答）时只做轻微调整
  - 验收：单测构造 2 次作答，断言不触发结构性调整
- [ ] 3.4 限频：同类信号当日累计 2 次才触发，每日结构性调整不超过 1 次
  - 验收：单测模拟同日多次信号，断言第二次之后只记录不调整
- [ ] 3.5 覆盖模式保护：任何调整不减少必修知识点覆盖
  - 验收：单测断言调整前后必修项数量不变
- [ ] 3.6 所有调整写入 `adjustment_log`，含被拦截的情形
  - 验收：拦截场景也能查到日志与拦截原因

## 4. 定期测验

- [ ] 4.1 三种触发入口：阶段全部必修项达标 / 距上次测验 ≥ 7 天 / 用户手动
  - 验收：三种入口都能生成测验
- [ ] 4.2 取题排除近期练过的原题，改用变式或新题
  - 验收：单测断言测验题集合与近期练习题目集合无交集
- [ ] 4.3 覆盖模式下每个必修知识点至少出现一次
  - 验收：单测断言覆盖完整性
- [ ] 4.4 测验无提示、作答完成前不给中间反馈
  - 验收：界面检查 + 单测断言中间态未返回判分结果
- [ ] 4.5 判分同口径更严：不做"部分正确"
  - 验收：单测断言只返回达标 / 不达标
- [ ] 4.6 未通过回退：标记需重练、重新排期、知识点进入加强模式
  - 验收：测验未通过后能在后续计划中看到该项
- [ ] 4.7 重考换新题，禁止复用上次测验题目
  - 验收：单测断言重考题目集合与上次无交集

## 5. 达标判定

- [ ] 5.1 训练项达标 = 判据满足且连续 2 次达标
  - 验收：单测覆盖"单次达标不算"与"连续两次达标算"
- [ ] 5.2 阶段达标：覆盖模式看必修项全达标，达成模式看阶段验收标准
  - 验收：两种模式各一组单测
- [ ] 5.3 任务达标 = 必修覆盖 100% 且最终测验通过
  - 验收：单测覆盖"覆盖满但测验未过"不达标的情形

## 6. UI

- [ ] 6.1 任务卡：信号标签与可选文本，三省改为可折叠的可选项
  - 验收：不写三省也能正常完成当日流程
- [ ] 6.2 冲突提示：自评与客观表现不一致时给出说明文案
  - 验收：构造冲突场景，页面出现提示
- [ ] 6.3 测验页：整卷作答、无提示、完成后统一给结果
  - 验收：作答过程中看不到对错
- [ ] 6.4 复盘页：新增信号分布、测验通过率、调整次数三个指标
  - 验收：三项均展示且带口径说明
