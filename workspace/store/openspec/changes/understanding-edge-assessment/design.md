# understanding-edge-assessment · 设计文档

## Context

### 背景

这一环决定路径"教什么"。若边缘定位不准，路径要么在教已经会的（浪费时间），要么在教还理解不了的（打击信心）。

现有实现是 3 道题 + 高/中/低档位，粒度不足以支撑逐知识点的取舍。

### 当前状态

- `baseline_service.py`：3 道诊断题、LLM 评分、档位判定、低档生成预训练清单
- `baseline_history` 表存的是档位历史
- 难度已有四档与依据口径（ADR-0010）
- 评测有 strict / fuzzy 双模式（ADR-0002）
- `periodic-assessment` 已定义测验的取题、无提示与判分约束
- md 已降级为导出物（ADR-0017）

### 约束

- 沿用 ADR-0001：LLM 出题与判分只产出结构化结果，**三态判定由规则层计算**
- 沿用 ADR-0007：不引入 embedding
- 沿用 ADR-0018：位置固定在选来源之后、生成路径之前
- 不规定知识点清单的维护方（与关键词白名单解耦）

### 利益相关方

- 个人版用户：他在用系统学自己的东西，希望别浪费时间
- 路径生成：消费三态结果决定跳过、重点与铺垫

## Goals / Non-Goals

**Goals:**

- 用尽量少的题量，定位每个知识点的理解边缘
- 输出可直接驱动路径生成的三态结果
- 探测成本可控且可跳过，不阻塞用户进入训练

**Non-Goals:**

- 不做固定测评题库、不做学习风格测评、不做跨知识点推理能力测量

## Decisions

### D1 探测对象：知识点清单

探测的测量对象是**知识点清单**，来源为**来源切片 + 验收标准**推导：

1. 从已导入来源的切片中抽取候选知识点（复用 `source-management` 的 `heading_path` 与切片内容）
2. 用验收标准过滤出与目标相关的知识点
3. 清单中的每个知识点都必须被探测覆盖

**本 change 不决定清单由谁维护**（AI 抽取后人工确认、还是管理层指定），只用它。这使得关键词白名单的去留与本设计解耦。

### D2 分层自适应探测

对每个知识点按难度 1 → 4 递进：

```
从难度 2 开始
  答对 → 升到难度 3；再答对 → 难度 4
  答错 → 降到难度 1
记录：在哪一档通过、在哪一档失败
```

**为什么从 2 开始**：最低档几乎人人都过、最高档几乎人人都失败，从中间起步能最快接近边界。

**题量控制**：单知识点最多 3 题（上行 2→3→4 或下行 2→1），全部知识点合计设总上限；探测过程展示"还剩 N 题"。

### D3 三态判定（规则层）

| 状态 | 判定条件 | 路径中的处理 |
|---|---|---|
| **已掌握** | 连续通过高档位（难度 3 与 4 均通过） | **跳过**，仅保留低频维护复习 |
| **边缘** | 中档通过（难度 2 与 3 通过）而高档（难度 4）失败 | **教学重点**，路径主力 |
| **未达** | 难度 1 即失败 | 先做**前置铺垫**，再进入训练 |

**判定由规则层依据"在哪一档通过/失败"计算，不由 LLM 给出状态**（ADR-0001）。
每个知识点保留判定依据（通过的档位与失败的档位），可追溯、可复核。

### D4 未达知识点的前置铺垫

为未达知识点生成基础概念与推荐资料，并在路径中排在对应知识点之前。
**不允许把未达知识点直接当作可训练项安排**——先铺垫再教。

铺垫内容同样要回指来源切片（沿用 `source-management` 的回指约束）。

### D5 跳过与兜底

用户可跳过探测。跳过后：

- 所有知识点按**中位难度（2 档）**起步
- 路径前几项刻意覆盖不同难度，用于快速试探
- 一旦积累足够作答数据，按 ADR-0010 的经验难度校准机制修正

**为什么允许跳过**：强制在用户还没看到计划前先考试会显著增加流失；而跳过的代价只是"前几项难度不准"，这个代价可以用现有校准机制吸收。

### D6 重测与边缘移动

边缘会随训练移动（学过的东西不再在边缘上）。重测入口：

1. **阶段切换时**：新阶段开始前重新定位受影响的知识点
2. **用户主动请求**：复用 `periodic-assessment` 的"我现在想验证一下"入口

重测使用与首次不同的题目（沿用 ADR-0016 的独立性约束），结果覆盖当前状态，同时保留历史记录以便回看"边缘怎么移动的"。

### D7 结果如何被路径生成消费

| 三态 | 路径生成的动作 |
|---|---|
| 已掌握 | 不生成训练项，仅生成低频维护复习项 |
| 边缘 | 生成为该阶段的主要训练项，难度起始取判定出的边界档位 |
| 未达 | 先生成前置铺垫项，铺垫达标后再生成正式训练项 |

覆盖模式下，**未达与边缘的知识点仍属必修**，不得因难度而省略；已掌握的知识点可标记为"已验证，不计入必修训练项"但仍保留在覆盖清单里。

## Risks / Trade-offs

| 风险 | 影响 | 处理方式 |
|---|---|---|
| 知识点清单质量差 | 探测覆盖不到真正的重点 | 清单可从来源切片重算；探测结果页面展示清单，允许用户增删 |
| 题量超出用户耐心 | 流失 | 总题量上限 + 进度提示 + 允许跳过 |
| 单题误判（蒙对/手滑） | 三态判错 | 每档判定结合上一档结果；关键分界处（难度 3）必要时追加一题；训练中可被实际表现修正 |
| 三态边界规则过死 | 大量知识点落在"未达" | 允许用户对判定结果提出异议并手动改档，改动留痕 |
| 探测题与后续训练题重复 | 后续训练测的是记忆 | 沿用 ADR-0016 的独立性约束，探测题进入"近期已用"集合被排除 |
| 与关键词白名单解耦后清单来源不稳 | 清单遗漏 | 本 change 只要求"能从来源推导"，来源明确时清单即可复算 |

## 验收方式

- 单测：升降档逻辑、三态判定三种分支、知识点覆盖完整性、跳过后的默认档位、题量上限
- 手动场景：导入一份资料后开始探测，结束后能看到每个知识点的三态与判定依据（在哪档通过、哪档失败）
- 手动场景：跳过探测后生成路径，所有训练项起始难度为中位
- 手动场景：边缘判定为"未达"的知识点，在路径中位于其前置铺垫之后
- 指标：探测题量分布、已掌握被跳过的比例、未达被前置的比例——**待实测，当前标【待验证】**
