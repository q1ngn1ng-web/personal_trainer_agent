## 1. 数据层

- [x] 1.1 新增 `plan_items` 表（到期日 / 训练 / 题目 / 轮次 / 锚点日 / 状态 / 原定日 / 原因）
  - 验收：`init-db` 后表可查看；`UNIQUE(training_id, item_key, round_index)` 生效（同一题同一轮次只有一条）
- [x] 1.2 `training_items.status` 新增 `practiced`（练过），`passed` 语义收窄为"达标"
  - 验收：迁移可重复执行；迁移后 `PRAGMA foreign_key_check` 为 0；老数据状态不丢
- [x] 1.3 `training_items` 增加**跨重生成稳定的键**（`item_key`），计划表与题库一律引用该键
  - 验收：连续生成两次路径后，已练过项的 `item_key` 不变、`plan_items` 不悬空、题库登记不失效
- [x] 1.4 统一"今天"的口径：新增本地时区取日函数（`src/core/plan.py: local_today`），排期先用；`log_date` / 限频的接入待下一批
  - 验收：单测固定时间点（本地 00:30 与 UTC 前一日）断言三处得到同一天
- [x] 1.5 `adjustment_log` 补齐"调整前后取值"（难度调整写 `difficulty_before` / `difficulty_after`）
  - 验收：一次难度调整能查到 `{"before": 2, "after": 3}`

## 2. 排期生成（纯函数 + 落库）

- [x] 2.1 整条路径 5 轮：以**训练创建日**为锚点，为每个训练项生成 +1 / +3 / +7 / +15 / +30 五个到期日（一层轮次 × 全部题）
  - 验收：9 月 20 日创建、12 道题的路径 → 5 轮 × 12 = 60 条计划项；轮次到期日为 9/21、9/23、9/27、10/5、10/20；第 5 轮之后不再产生计划项
- [x] 2.2 当日任务取数：`due_date <= 今天` 且未完成，同一训练项**只取最早未完成的那一轮**
  - 验收：连缺 3 天后只出现第 1 轮的项（不出现第 2、3 轮）；第 1 轮完成后才出现第 2 轮
- [x] 2.3 生成幂等：同一路径重复生成不产生重复计划项
  - 验收：连续调用两次，`plan_items` 行数不变
- [x] 2.4 路径确认后自动生成，并把摘要返回页面
  - 验收：确认路径后首页立即能看到今天的任务；生成失败不阻塞确认（可手动重排）
- [x] 2.5 老训练补计划：已确认且有路径但无计划的训练，首次进入时生成一次
  - 验收：第二次进入不重复生成；无路径的训练不生成空计划
- [ ] 2.6 不存在"每周频次""休息日"概念：排期代码中不得再有 `weekly_frequency` 参与日期计算
  - 验收：单测断言同样的路径在 `weekly_frequency` 取不同值时排期结果完全相同
- [x] 2.7 单日负荷只提示不裁剪：展示当日预计总时长，超过每日上限时提示，但不得裁剪任何题
  - 验收：把每日上限设为 5 分钟时，当日任务条数不变，只多出一条超限提示

## 3. 累计与顺延

- [x] 3.1 未完成的计划项累计到次日（查询语义：`due_date <= 今天` 且未完成），并保留 `original_date`
  - 验收：昨天有 2 项未完成，今天这 2 项出现在今天且原定日期可查
- [x] 3.2 累计不改变轮次顺序：后一轮次必须排在前一轮次完成之后
  - 验收：第 1 次未完成时，第 2 次不得先于它完成（单测构造乱序完成）
- [x] 3.3 长期未完成不丢项、不自动裁剪、不自动延长周期
  - 验收：连续 7 天未完成，计划项一条不少，且没有自动改期到未来的"洗白"行为
- [x] 3.4 手动跳过：必须记原因，且不计为完成
  - 验收：跳过项不出现在完成统计里，原因可查

## 6. 题库与两周测验排期

- [x] 6.1 新增 `question_bank` 表：登记题目内容 / 题源切片 / 所属知识点 / 练过次数 / 入池时间 / 冷却期
  - 验收：一张表能查到"这道题来自哪里、练过几次、是否可抽"
- [x] 6.2 题目内容来源打通：探测题文本（或训练项标题）+ 来源切片指针写入题库
  - 验收：八股类 PDF 切片能被登记为可复用的题目，而不是每次重新生成
- [x] 6.3 练过后自动登记入题库，并设 `cooldown_until = 最近练过日 + 14 天`
  - 验收：一次练过 → 题库新增/更新一条，`practiced_count` 与 `cooldown_until` 同步更新
- [x] 6.4 每两周生成一次测验任务并排入计划（`kind='assessment'`，锚点 = 训练创建日 +14/+28/…）
  - 验收：创建日 + 14 天出现一条测验任务；同一周期只生成一次；训练结束后不再生成
- [ ] 6.5 抽题满足 ADR-0016：排除近期练过的原题（`drawable_questions` 已实现），**覆盖阶段必修知识点待 `periodic-assessment` 落地**
  - 验收：单测断言抽出的题目集合与"冷却期内练过的原题目集合"无交集；覆盖模式下一个必修知识点不少
- [ ] 6.6 测验的取题 / 判分 / 达标仍归 `periodic-assessment`，本 change 只负责排期与题库
  - 验收：本 change 的 spec 不含判分规则；交叉引用写在 design.md
