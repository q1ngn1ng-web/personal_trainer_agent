# training-plan-and-daily-view · 任务清单

> 按依赖顺序编号。每个任务写明验收方式。选型见 ADR-0001 / ADR-0011 / ADR-0017 与本 change 的 design.md。

## 1. 数据层

- [ ] 1.1 新增 `plan_items` 表（日期 / 训练 / 训练项 / 类型 / 状态 / 预计时长 / 生成来源 / 原因）
  - 验收：`init-db` 后表可查看；`kind` 与 `status` 只接受枚举值；`UNIQUE(training_id, item_id, plan_date)` 生效（重复插入报错）
- [ ] 1.2 `training_items.status` 新增 `practiced`（练过），`passed` 语义收窄为"达标"
  - 验收：迁移可重复执行；迁移后 `PRAGMA foreign_key_check` 为 0；老数据状态不丢
- [ ] 1.3 统一"今天"的口径：新增本地时区取日函数，`plan_date` / `log_date` / 信号限频共用
  - 验收：单测固定时间点（本地 00:30 与 UTC 前一日）断言三处得到同一天
- [ ] 1.4 `adjustment_log` 补齐"调整前后取值"（写入 `detail`）
  - 验收：一次难度调整能查到 `{"before": 2, "after": 3}`

## 2. 排期生成（纯函数 + 落库）

- [ ] 2.1 练习日序列：以训练创建日为锚点，第 1 次在创建日次日，之后按 `7 / weekly_frequency` 天递推（round half up）
  - 验收：`3 次/周` 得到偏移 `1, 3, 6, 8, 10, 13, ...`；`7 次/周` 得到每天；`1 次/周` 得到偏移 `1, 8, 15, ...`；任取连续 7 天恰好 `weekly_frequency` 个练习日
- [ ] 2.2 锚点已过去时对齐：创建后隔 N 天才生成计划时，跳过过去的练习日，从今天起继续对齐
  - 验收：创建日 + 5 天后生成计划，计划中不存在过去日期的计划项，且仍在同一节奏上
- [ ] 2.3 单日容量填充：按阶段顺序与 `daily_budget_minutes`、每日条数上限填充训练项
  - 验收：任一日计划项时长合计 ≤ 预算；条数 ≤ 上限；阶段顺序不被违反
- [ ] 2.4 生成幂等：同一路径重复生成不产生重复计划项
  - 验收：连续调用两次，`plan_items` 行数不变
- [ ] 2.5 路径确认后自动生成，并把生成结果摘要返回给页面
  - 验收：确认路径后首页立即能看到今日计划；生成失败不阻塞确认（可手动重排）
- [ ] 2.6 老训练补计划：已确认且有路径但无计划的训练，首次进入时生成一次
  - 验收：第二次进入不重复生成；无路径的训练不生成空计划
- [ ] 2.7 投入参数变更后重排：只重排**未练过**的项，已练过的项与历史不动
  - 验收：改 `weekly_frequency` 后，`practiced` 项日期不变，`planned` 项按新频率重排

## 3. 间隔复习

- [ ] 3.1 练过后按 1/3/7/15/30 天插入复习项（`kind='review'`）
  - 验收：单测断言一次练过生成 5 条复习项，日期分别为 +1/+3/+7/+15/+30
- [ ] 3.2 复习日直接落位（即使落在休息日也不挪动），新学让位
  - 验收：复习日期严格等于"练过日 + 1/3/7/15/30"；当天容量不足时被顺延的是新学项，不是复习项
- [ ] 3.3 复习项占当日上限：≤ 当日计划项总数的 1/2 且 ≤ 2 条
  - 验收：超出上限的复习项排在后续日期，且仍保持间隔阶梯的先后顺序
- [ ] 3.4 复习项不重复插入（同一训练项同一日期只有一条）
  - 验收：重复标记练过不产生重复复习项

## 4. 今日视图（首页 + 任务卡）

- [ ] 4.1 首页「今日训练」区块：跨训练按主题分组展示今日计划项与合计时长
  - 验收：两个训练同一天有项时，首页一次展示两组，且合计正确
- [ ] 4.2 今日任务卡改为从 `plan_items` 读，支持"全部 / 仅某训练"范围切换
  - 验收：跨训练视图包含全部今日项；单训练视图只含该训练；两种视图条数自洽
- [ ] 4.3 空态：今天没有计划项时显示"休息日 + 下次练习日与预计项数"
  - 验收：休息日不再出现"没有任务"的空白，也不再退回"当前阶段前 5 项"的兜底
- [ ] 4.4 待补区：`plan_date < 今天` 且未勾选的项显式展示
  - 验收：昨天未勾的项今天出现在待补区，且**不消失**
- [ ] 4.5 移除 `today_tasks()` 的游标语义
  - 验收：`path_service.today_tasks` 不再被任务卡调用（或改为薄封装）；相关单测更新

## 5. 勾选语义与状态

- [ ] 5.1 勾选写 `practiced`（计划项 + 训练项），取消勾选回到 `planned` 但保留 `practiced_at`
  - 验收：勾选后训练项为 `practiced` 且**不等于** `passed`；取消后历史时间仍在
- [ ] 5.2 UI 文案去掉"已达标"，改为"今天练过"
  - 验收：全站搜索无"已达标"文案（`training-execution-feedback` 5.1 落地后再改回）
- [ ] 5.3 勾选写回计划项状态并同步当日进度统计
  - 验收：勾选后首页今日训练与完成度同时更新

## 6. 顺延与调整执行点

- [ ] 6.1 顺延动作：把待补项 `plan_date` 改到今天（写 `reason`），或标记 `skipped`（必填原因）
  - 验收：顺延后项出现在今天；跳过不减少总计划项数
- [ ] 6.2 `reduce_load` 执行点：次日条数减半并顺延被削减项
  - 验收：模拟 `too_much` 结构性调整，次日计划条数下降且总量不变
- [ ] 6.3 `raise_difficulty` / `lower_difficulty` 执行点：改 `difficulty_tier`（1..4），日期不变
  - 验收：难度变化后计划日期不变；`adjustment_log.detail` 记录前后值
- [ ] 6.4 `expand_scope` 执行点：在下一个练习日插入相邻知识点的计划项
  - 验收：插入后总量增加且落在下一个练习日；无相邻项时只记录并提示

## 7. 规格与收尾

- [ ] 7.1 更新 `daily-execution` spec：今日任务卡的数据源改为训练计划表，删除对复习日历文件的依赖
  - 验收：`openspec validate --all --store store` 通过
- [ ] 7.2 更新 `progress-dashboard` spec：首页新增「今日训练」区块
  - 验收：同上，且「仪表盘只读」requirement 未被削弱
- [ ] 7.3 老文件式路径（`schedule_service` 的 units 分支 + `04_复习日历`）标注为 legacy
  - 验收：代码注释与 codemap 标注；新链路不再依赖
- [ ] 7.4 回填证据：排期与预算偏差、计划完成率、顺延次数、预计完成日偏差（未实测的标【待验证】）
  - 验收：`workspace/evidence/` 有一份报告，数字有出处（口径 / 样本 / 时间窗口）
- [ ] 7.5 写 `workspace/record/` 变更记录 + 提交
  - 验收：记录含变更摘要、影响范围、相关文件、关联 change id
- [ ] 7.6 archive 本 change，并把新增 spec 的 `Purpose` 从 `TBD` 改成一句话
  - 验收：`openspec validate --all --store store` 全绿，spec 的 Purpose 不再是 TBD
