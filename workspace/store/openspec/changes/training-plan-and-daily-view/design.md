# training-plan-and-daily-view · 设计文档

## Context

### 背景

训练场景里"今天练什么"是一等公民。用户的真实心智是：

**创建主题 → AI 把题目排进计划表 → 首页看今天要练哪些主题的哪些题 → 勾选练过 → 每道题在第 1/3/7/15/30 天各练一次（共 5 次）→ 练完即止**；
期间**每两周做一次测验**，题目从**练过的题库**里抽。

现在缺的正是这层。路径只表达顺序与阶段（`training_paths` / `path_stages` / `training_items`），
"今天"由 `path_service.today_tasks()` 用**游标**现算：当前阶段待练项前 5 条 + 当前阶段已通过项前 2 条。

### 当前状态

- `daily-execution` spec 要求"按当前日期从复习日历抽取 + 1-3-7-15-30 间隔"，但其载体（十份 md）已按 ADR-0017 废弃 → **需求与载体脱节**
- `schedule_service.extract_today_tasks()` 仍保留老实现（读 `trainings.schedule` 的 units 做间隔复习），新链路实际走 `path_service.today_tasks()` 兜底（`schedule_service.py:153-188`）
- `training_items` 有唯一自增主键 `id`，但**没有题目内容字段**（只有 title / item_type / difficulty / knowledge_point / source_chunk_ids）；
  真正的题目文本只存在于来源切片 `source_chunks.text` 与探测题 `edge_assessments.question`
- `training_items` 的 id **不稳定**：`save_skeleton` 先删后插（`path_service.py:341-359`），路径重新生成会分配全新 id
- 勾选把 `training_items.status` 写成 `passed`（`page_daily.py:93-95`）
- 用户参数是"周期 × 每周频次 × 每次时长"（ADR-0006），预算由三者相乘得到（`path_service.py:86`）

### 约束

- 沿用 ADR-0001：**LLM 不排日期**，排期是规则层的确定性计算（纯函数，可单测）
- 沿用 ADR-0011：单次负荷与总量分离；未完成项的处置由用户决定，系统不擅自改总量
- 沿用 ADR-0016：**测验题不得取自刚练过的原题**
- 沿用 ADR-0017：结构化数据是唯一真相，md 只是导出物
- 沿用 ADR-0009：主视图是列表 + 进度，不画模型生成的图
- 不做达标判定、不做逐次作答记录（属 `training-execution-feedback`）

### 利益相关方

- 用户本人：打开首页就知道今天练哪些主题的哪些题，不想逐个主题找
- 背八股 / 背算法题的自学者：同一道题要按间隔练到熟，且要能看到"我练到第几次了"
- 面试讲解：需要能说清"为什么是固定 5 次 + 幂等题库"，而不是"模型随便排"

## Goals / Non-Goals

**Goals:**

- "今天该练哪些题"由**计划表**回答，且一眼能看到多个主题在同一份今日训练里
- 每道题**恰好 5 次**（+1/+3/+7/+15/+30），练完即止
- 没做完的项**累计到次日**，不丢、不裁剪
- "练过"与"达标"在数据上分开；"练到第几次"可查
- 每两周一次测验，题目来自**有稳定标识的题库**，且不与近期原题重复（ADR-0016）

**Non-Goals:**

- 不做日历月视图、拖拽改期
- 不做通知推送、不做 Agent 侧交付形态
- 不做跨训练的总负荷再平衡（只展示合计）
- 不做达标判定、作答记录、测验判分（各有归属）
- 不做维护复习（第 6 次及以后）——与 ADR-0018 的差异见 D2

## Decisions

### D1 计划表是排期的唯一载体：`plan_items`

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `training_id` | 所属训练 |
| `item_id` | 指向 `training_items.id` |
| `round_index` | 第几次：1..5（测验任务用 `kind` 区分，轮次为 0） |
| `kind` | `train` / `assessment` |
| `due_date` | 到期日（本地日期 `YYYY-MM-DD`） |
| `anchor_date` | 该题的锚点日（被排入计划的那天） |
| `original_date` | 首次到期日（累计顺延后仍可查） |
| `status` | `planned` / `practiced` / `deferred` / `skipped` |
| `planned_minutes` | 预计时长 |
| `practiced_at` | 练过时间 |
| `reason` | 顺延 / 跳过 / 调整原因 |
| `created_at` | 创建时间 |

约束：`UNIQUE(training_id, item_id, round_index)` —— 保证"同一道题的第 N 次"只有一条，重复生成幂等。

**为什么以到期日为键**：唯一能表达"哪天练哪几道"的键就是日期。`daily_logs` 是**打卡记录**（用户点了什么），不是计划，两者不能互相代替。

### D2 每道题固定 5 次：锚点 + 1/3/7/15/30

- **锚点 `anchor_date`** = 该训练项**被排入计划的那一天**（第一批题就是确认路径的当天）；
- 到期日 = `anchor_date + 1`、`+3`、`+7`、`+15`、`+30` 天，`round_index = 1..5`；
- **第 5 次之后不再产生任何计划项**；
- 例：9 月 20 日排入 → 9 月 21、23、27 日与 10 月 5、20 日各一次；10 月 20 日之后该题结束。

**为什么锚点是"入计划日"而不是"训练创建日"**：题目必须**分批引入**（受每日时长上限约束）。
若所有题都以创建日为锚点，第一天就得把整条路径全练一遍。

**与 ADR-0018 的差异（显式记录）**：ADR-0018 提到"已掌握只保留低频维护复习"，本模型按用户要求**不做维护复习**——练完 5 次即结束。
"已掌握"的知识点仍然只被跳过（不进路径），逻辑不冲突。

### D3 与"每周频次 / 休息日"解耦

排期**不再使用** `weekly_frequency`，也不设"休息日"：每天都可能有到期任务（来自不同题目的阶梯），某天没有到期任务就是自然空档。

| 参数 | 现状（ADR-0006） | 本 change |
|---|---|---|
| `horizon_weeks` 周期 | 参与预算 | **废弃**（周期由最后一道题的第 5 次到期日自然决定） |
| `weekly_frequency` 每周次数 | 参与预算 | **废弃**（节奏由固定阶梯决定） |
| `daily_budget_minutes` 每次时长 | 参与预算 | **保留**，含义改为"每天新引入题目的时长上限" |

这属于技术选型变更：按 AGENTS.md 硬性门禁，**实现前 MUST 先写 ADR-0021 取代 ADR-0006 的参数部分**（任务 0.1），
并据此重写 `check_budget` 的口径（从"总量分钟数"改为"每日上限 + 总题量"）。

### D4 每天引入新题：按阶段顺序 + 每日时长上限

1. 每天从路径中按**阶段顺序 → 阶段内顺序**取尚未排入计划的训练项；
2. 累计预计时长（题型默认值 `memory=10 / comprehension=15 / practice=20 / prerequisite=15`，与 `check_budget` 口径一致），直到超过每日上限为止（**至少允许 1 道**，避免上限过小造成死循环）；
3. 已引入的题立刻生成它的 5 个到期日（D2）；
4. **阶段顺序是硬约束**：前一阶段尚有未完成的训练项时，后一阶段的新题 MUST NOT 先被引入；
5. 全部题目引入完毕后不再新增；训练在最后一道题的第 5 次完成后自然结束。

**每天的负荷** = 当天到期的阶梯项 + 昨天累计未完成项 + 当天新引入的题。
三者合计超过上限时，**优先保留到期项与累计项**，把新题引入推迟——到期项不能消失，新题可以晚一天。

### D5 累计顺延：不丢项、不裁剪

- 到期未完成的计划项，次日 `due_date` 改为次日，`original_date` 保留首定日期，`status='deferred'`（仍可勾选）；
- **轮次顺序硬约束**：同一道题的第 N 次未完成时，第 N+1 次 MUST NOT 排到它前面（避免"跳过第 1 次直接做第 5 次"的假进度）；
- 长期未完成（如连续 7 天）时，计划项**一条不少**，只是整体后移；系统 MUST NOT 自动延长周期、MUST NOT 自动裁剪；
- 用户可主动"跳过"某项（`status='skipped'` + 必填原因），跳过**不计入完成**，也不减少覆盖统计。

### D6 勾选语义：`practiced` ≠ `passed`

- 勾选计划项 → `plan_items.status='practiced'` + `training_items.status='practiced'`（新增状态值）+ `practiced_at`；
- 取消勾选 → 回到 `planned`，但**保留 `practiced_at` 历史**（不抹掉证据）；
- `passed` **只能**由达标判定写入（`training-execution-feedback` 5.1：判据满足且连续 2 次达标）；
- 达标判定落地前，UI 文案 MUST 用"今天练过"，MUST NOT 出现"已达标"（现状 `page_path.py:20` 的「✅ 已达标」需改）。

`training_items.status` 枚举需要新增值 → **SQLite 无法改 CHECK 约束，必须重建表**，
沿用 HANDOFF 第 5 节的迁移三件套（`isolation_level=None` + `foreign_keys=OFF` + `legacy_alter_table=ON` + 显式事务 + `foreign_key_check`）。

### D7 题目唯一标识必须跨重生成稳定（题库的硬前提）

现状 `training_items.id` 会随路径重生成变化，因此：

- 为训练项引入**稳定题目键 `item_key`**（建议 `sha1(training_id + knowledge_point + 规范化 title)`，或人工可读的 `T{training_id}-{seq}` 并按知识点匹配沿用）；
- 重新生成路径时：
  - **已练过或已在计划中**的训练项 MUST 保留（沿用原 `item_key` 与原 `training_items.id`）；
  - 新增项分配新键；被移除但**已练过**的项 MUST NOT 删除（标记"已废弃"），因为题库与历史记录要指向它；
- `plan_items.item_id` 与 `question_bank.item_key` 的引用因此永远有效。

**不做这一步，"练过的 ID 入题库"就是空话**：行会被删掉，ID 会指向下一个新题。

### D8 今日视图：跨训练聚合为主入口

- **首页顶部**新增「今日训练」区块：查询 `due_date = 今天`（含当天被累计的项），按训练分组，显示每组条数与合计时长，以及跨训练合计；
- 提供两个入口：进入**今日任务卡（跨训练）**、进入某训练的**单训练视图**；
- 「今日任务卡」保持单页，增加"全部 / 仅某训练"范围切换；每项显示**第几次 / 共 5 次**；
- 今天没有任何到期任务时显示「今天没有任务（下次有任务的日期：X 月 X 日，预计 N 项）」——**空态必须是有信息的空态**；
- 首页指标区保持只读（`progress-dashboard` 的「仪表盘只读」requirement 不变）。

与 `org-and-roles` 的边界：企业版回答"**谁**要练"（培训任务分配给人），本 change 回答"**哪天**练什么"。

### D9 题库与每两周测验（衔接 ADR-0016）

**题库 `question_bank`**

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `training_id` | 所属训练 |
| `item_key` | 稳定题目标识（D7） |
| `source_chunk_ids` | 题目内容来源（八股资料里切片本身常是"题目 + 答案"） |
| `knowledge_point` | 知识点 |
| `item_type` / `difficulty_tier` | 题型与难度 |
| `practiced_count` | 练过次数（0..5） |
| `last_practiced_at` | 最近练过时间 |
| `banked_at` | 入池时间 |
| `cooldown_until` | 冷却期结束日，早于该日不可被抽中 |
| `status` | `active` / `retired` |

规则：

1. **练过即入池**：第 1 次练过时登记（含内容来源），之后每次更新 `practiced_count` 与 `last_practiced_at`；
2. **练完 5 次仍留在池里**（`practiced_count = 5`），作为后续测验的蓝本；
3. **冷却期**：入池后设置 `cooldown_until`（默认 = 练过日 + 14 天，或"练满 3 次"，取值待定见 Open Questions）。
   这是 **ADR-0016 的硬要求**：直接抽刚练过的原题，测的只是短时记忆；
4. **抽题 MUST 排除冷却期内的题目**，并使用变式题（换场景 / 换问法 / 改条件）；
5. 覆盖模式下每个必修知识点 MUST 至少出现一次（沿用 `periodic-assessment`）。

**每两周一次测验**

- 触发：距上次测验 ≥ 14 天（按训练分别计算，首次测验的锚点见 Open Questions）；
- 生成一条 `plan_items(kind='assessment')`；**测验内容不可由用户挑选**（ADR-0016 决策 6）；
- 判分、无提示、未通过回退重练等规则属 `periodic-assessment`，本 change 不重复定义。

### D10 日期口径统一为本地时区

全部"今天"的判定统一走一个函数（如 `src/core/clock.py: today_local()`，时区 `Asia/Shanghai`，可用环境变量覆盖），
`plan_items.due_date`、`daily_logs.log_date`、信号限频的"当天"都用它。修掉现在"限频按 UTC、打卡按本地"的分叉。

- 新增 `plan_items` / `question_bank` 走 `tables.sql` + `migrate.py`。**注意**：本轮审计已发现两份 DDL 会漂移
  （`workspace/evidence/20260920-服务层代码审计.md` S3，真实库里 `idx_llm_calls_purpose` 与 `yidx_llm_calls_purpose` 同时存在），
  实现时 SHOULD 只保留一份真相，或至少加一致性检查；
- `training_items` 新增 `item_key`（回填：按 `knowledge_point + title` 派生）+ `practiced` 状态 → 重建表（迁移三件套）；
- 老训练（已 confirmed、有路径、无计划）：首次进入时按当前路径生成计划，**锚点 = 生成当天**（不追溯过去）；
- 老训练（无路径）：不生成空计划，首页提示"尚未生成训练计划"；
- `schedule_service` 的老文件式分支：新链路不再走，保留代码并标注 legacy。

## Risks / Trade-offs

| 风险 | 影响 | 缓解 |
|---|---|---|
| 题目标识回填不准确 | 题库与历史指向错误 | 回填用 `(training_id, knowledge_point, 规范化 title)`；重生成时按同键匹配保留；单测覆盖 |
| 新题引入 + 到期项 + 累计项叠加 | 单日负荷超出预期 | 优先保留到期与累计项，推迟新题引入；首页显示当日合计时长 |
| 冷却期过短 | 测验退化为短时记忆（ADR-0016 失效） | 默认 14 天 / 练满 3 次；单测断言"冷却期内不被抽中" |
| 长期未完成导致雪崩（累计越滚越多） | 用户放弃 | 待补区按原定日期分组显示；可跳过并记原因（不计完成） |
| 参数模型变更影响既有 UI | 路径页的"周期/每周次数"控件失去意义 | 任务 0.1 先写 ADR-0021 再改 UI；过渡期两参数只读展示为"历史值" |
| 表结构与状态枚举变更多 | 迁移是最高风险动作 | 复用已演练的迁移三件套 + 迁移后 `foreign_key_check` 自检 |

## 待决问题（Open Questions）

1. **锚点确认**：本设计把锚点定为"该题**被排入计划的那一天**"（分批引入，第一批就是确认路径当天）。
   若你想要的是"整条路径从创建日起算，第 1/3/7/15/30 天各过一遍全部题"，则 D2/D4 需要改写。
2. **每日时长上限**：沿用 `daily_budget_minutes`（当前 5–240 分钟）作为"每天新题时长上限"，还是改成"每天最多几道题"？
3. **冷却期取值**：练过满 **14 天**、练满 **3 次**、还是两者取其一？直接决定 ADR-0016 的落实强度。
4. **测验锚点**：首次测验从训练创建日算（第 14 天），还是从"该训练第一次练过"算？
5. **题目内容存哪**：题库保存"题目 + 答案"文本本身（从来源切片抽），还是只存 `source_chunk_ids` 指针？
   存文本更稳（来源重解析不会丢），但要与 ADR-0017 的"单一真相"协调。
