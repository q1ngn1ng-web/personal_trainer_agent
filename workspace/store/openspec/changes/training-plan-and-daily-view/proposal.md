# training-plan-and-daily-view · 训练计划表与今日视图

## Why

整条链路的前半段已经通了：目的确认 → 资料 → 理解边缘 → 路径。但**路径只是"顺序"，没有"哪一天练什么"**。

`training-path-generation` 把每日排期明确列为非目标（"不做每日排期（属调度器）"，见其 `design.md:39`），
而这个"调度器"**没有任何 change 拥有它**。于是新链路用了一个临时代替品：

```
today_tasks() = 当前阶段里还没练的项，取前 5 条 + 当前阶段已通过项的前 2 条
```

这是一个**游标**，不是计划表，带来四个后果：

1. **每一天都有任务，但看不出"这是第几次"**：游标对"今天"没有概念，用户看不到"这道题我该练第几次、今天到底该练哪些"。
2. **没有入口在首页**：今日任务必须带着 `?training_id=` 进某个主题才能看到；首页只有指标与训练列表。
3. **练过就消失**：勾完当前阶段的项，第二天游标跳到下一阶段，那道题的"第 3 天 / 第 7 天 / 第 15 天 / 第 30 天"再也不会回来——**固定 5 次巩固完全不存在**。
4. **勾选即达标**：勾选把训练项直接写成 `passed`，"练过"与"达标"共用一个状态；而"练过几次""题库里有哪些题"无处存放。

而**按日期排的复习计划本来就是需求**：已归档的 `daily-execution` spec 原文写着
「系统 SHALL 根据「复习日历」抽取**当前日期**的待办任务」与「复习项按 SM-2 简化间隔（1-3-7-15-30）……抽取」。
它当时的载体是十份 md 里的 `04_复习日历.md`；ADR-0017 把十份 md 降级为导出物之后，
**这个需求的载体消失了，实现换成了游标**。本 change 把载体补回来：从"文件里的复习日历"换成"数据库里的训练计划表"。

## What Changes

- 新增**训练计划表**（`plan_items`）：以**到期日**为排期载体，一条计划项 = （到期日 × 训练 × 训练项 × 轮次）
- 新增**固定 5 次阶梯**：每道题练**恰好 5 次**，以"该题被排入计划那天"为锚点，到期日为 **+1 / +3 / +7 / +15 / +30 天**；**第 5 次之后不再出现任何计划项**（不安排维护复习）
- **取消"每周训练次数"与"休息日"概念**：排期不再依赖 `weekly_frequency`；每天是否练由"当天到期的阶梯"决定
- 新增**每天引入新题**：按阶段顺序与**每日时长上限**把新题排进各天；后一阶段不得插到前一阶段之前
- 新增**累计顺延**：当天没完成的项**累计到次日**继续出现并保留原定日期；不删项、不裁剪、不自动掩盖
- 新增**首页「今日训练」**：跨训练聚合当天的计划项，按主题分组（"今天：Redis 持久化 3 题 · 算法 2 题"）；今日任务卡支持**跨训练视图**与**单训练视图**
- **勾选语义收敛为「练过」**：写 `practiced`，**`passed` 只能由达标判定写入**（属 `training-execution-feedback` 任务 5.1）
- 新增**每两周一次测验**并排入计划（`kind='assessment'`），测验题**从题库抽取**
- 新增**题库**（`question_bank`）：**每道题有唯一且稳定的标识**，练过后入池，练完 5 次仍保留；抽取时 MUST 满足 ADR-0016（**排除近期练过的原题**，用变式题，覆盖必修知识点）——因此入池后还有**冷却期**
- **题目标识稳定性是硬前提**：现有 `training_items.id` 在路径重新生成时会被重新分配（`save_skeleton` 先删后插），MUST 先补一个跨重生成稳定的题目键，否则"练过的 ID 入题库"会指向已经消失的行
- 统一**日期口径**为本地时区（`Asia/Shanghai`），修掉现在"信号限频用 UTC、打卡用本地"的分叉
- 把 `adjustment_log` 的动作接到执行点：`reduce_load` → 次日新题数量、`raise_difficulty` / `lower_difficulty` → `training_items.difficulty_tier`

### 关键取舍

| 选择 | 备选方案 | 放弃理由 |
|---|---|---|
| **每道题固定 5 次（+1/+3/+7/+15/+30）** | 按"每周练几次"排日历 | 训练目的是把题练到熟，间隔阶梯本身就是排期；"每周几次"是手段指标，用户不需要它，也解释不了"这道题我练到第几次了" |
| **锚点 = 该题入计划那天** | 以训练创建日为锚点，所有题同一天开始 | 题目要分批引入（受每日时长上限约束），同一锚点会让第一天塞满整条路径 |
| **未完成累计到次日** | 到期即作废 / 自动顺延到未来 | 用户明确要求"有事就累计到下一天"；作废等于悄悄降覆盖 |
| **练完 5 次即结束** | 加"低频维护复习"（60/120 天） | 用户明确要求"练完不再练了"；维护复习留待后续（与 ADR-0018 的差异在此显式记录） |
| **题库用稳定题目标识** | 直接用 `training_items.id` | 路径重生成会删旧行、分配新 id → 题库与计划全部悬空 |
| **练过入池 + 冷却期后才可抽** | 练过即可直接抽为测验题 | **直接违反 ADR-0016**（"测验题不得取自刚练过的原题"，测出来是短时记忆） |
| **跨训练聚合视图作为主入口** | 保持"逐个主题找今日任务" | 用户心智是"打开就看今天练哪些主题的哪些题"；多主题并行时逐个找必然漏 |
| **取消老 spec 的「概念/读/写 3:4:3 硬比例」** | 保留比例约束 | 新链路题型来自路径生成（memory / comprehension / practice / prerequisite），硬比例会与"覆盖模式必须覆盖全部必修知识点"冲突；题型分布改为**展示维度** |

详见 `workspace/decisions/ADR-0001`（排期由规则算）、`ADR-0016`（排除近期原题）、`ADR-0017`（十份 md 是导出物，不是数据源）。

## 非目标（Non-goals）

- **不做达标判定**：`passed` 的写入规则属 `training-execution-feedback` 任务 5.1（连续 2 次达标）
- **不做逐次作答记录与准确率**：属该 change 的任务 1.3（`assessments` / `assessment_items`）
- **不做测验的取题算法与判分**：判分 / 无提示 / 未通过回退重练属 `periodic-assessment`；本 change 只负责"每两周生成一次测验任务 + 题库登记与冷却期"
- **不做维护复习（第 6 次及以后）**：用户明确"练完不再练了"
- **不做日历月视图（拖拽改期）**：第一版只做"今天"与"待补"
- **不做通知与推送**：Agent/Codex 侧每天推任务是另一个交付形态问题，需单独决策（本 change 只保证数据层能支撑）
- **不做企业版的培训任务分配**：属 `org-and-roles` 的 `training-assignment`
- **不做跨训练的总负荷再平衡**：多个训练同一天有任务时，第一版只展示合计，不自动削减
- 不引入第三方调度库（APScheduler 等）：排期是纯函数 + 表，不需要常驻调度进程

## Capabilities

### New Capabilities

- `training-plan`: 训练计划——固定 5 次阶梯、每天引入新题、到期日聚合、累计顺延、计划变更留痕
- `question-bank`: 题库——题目唯一稳定标识、练过入池、冷却期与抽取约束（衔接 ADR-0016）

### Modified Capabilities

- `daily-execution`: 改写「系统呈现今日任务卡」——数据源从复习日历文件改为训练计划表，并定义跨训练聚合视图、单训练视图与待补区（**有意不改「用户能勾选完成任务并填写三省」**，该 Requirement 正被 `training-execution-feedback` 修改，避免 delta 冲突；勾选语义写进新 capability `training-plan`）
- `progress-dashboard`: 改写「首页展示训练列表与项目说明」，在首页顶部增加「今日训练」区块

## Impact

- **代码**：`src/db/`（新增 `plan_items` / `question_bank` 表 + `training_items` 稳定键 + 迁移）、`src/services/`（新增 `plan_service`：阶梯生成 / 新题引入 / 累计顺延；`path_service.today_tasks` 改为从计划表读）、`src/ui/`（首页今日训练区块、任务卡跨训练聚合、勾选改为 `practiced`）
- **数据**：新增两张表；`training_items` 增稳定键与 `practiced` 状态；老训练没有计划 → 首次进入时补生成一次（幂等）
- **参数模型变更**：`weekly_frequency` / `horizon_weeks` 不再参与排期与预算（`budget_minutes` 的"周期 × 频次 × 时长"口径需要重写）；按 AGENTS.md 硬性门禁，**实现前必须先写 ADR-0021 取代 ADR-0006 的投入参数模型**（任务 0.1）
- **ADR 关系**：ADR-0001 沿用；ADR-0006 的参数部分被 ADR-0021 取代；ADR-0011 的"单次负荷与总量分离 + 顺延由用户定"沿用；ADR-0016 约束题库抽取；ADR-0017 / 0009 不变；ADR-0018 的"低频维护复习"在本模型下不做（差异显式记录）
- **依赖**：无新增第三方依赖
- **测试**：5 次阶梯生成、每日时长上限、累计不丢项、轮次顺序、跨训练聚合、题库稳定标识、抽题冷却期
- **证据**：每题 5 次的实际完成率、累计顺延次数、测验覆盖率、抽题与原题的相似度抽检——**待实测，标【待验证】**

## 与进行中 change 的协调

| change | 关系 | 处理 |
|---|---|---|
| `training-path-generation`（16/29） | 只产出顺序与阶段，明确把"哪一天练"留给调度器 | 本 change 消费其 `training_items`，不改其 spec |
| `training-execution-feedback`（13/33） | 拥有 `learning-signal` 的动作规则、`daily-execution` 的勾选 Requirement、`periodic-assessment` 的判分 | **不重叠修改**：勾选语义写进 `training-plan`；测验判分/达标仍归 `periodic-assessment`，本 change 只做排期与题库 |
| `understanding-edge-assessment`（12/30） | 提供逐知识点三态，是路径输入 | 无接口冲突 |
| `org-and-roles`（0/29，已后置） | 企业版"培训任务"是"谁要练"，本 change 是"哪天练什么" | 边界在 design D8 说明，不改其 spec |

**归档顺序**：本 change 与 `training-execution-feedback` 无 Requirement 重叠，可任意顺序归档；
但在达标判定（5.1）落地前，勾选只能写"练过"，UI 文案 MUST NOT 出现"已达标"。
