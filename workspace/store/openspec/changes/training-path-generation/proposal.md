# training-path-generation · 训练路径生成

## Why

前两步已经把输入准备好了：`goal-clarification-confirm` 产出**已确认的目的**（学什么、到什么程度、怎么算学会），`training-source-selection` 产出**可用的资料来源**。现在缺的是把这两样变成一条能执行的路径。

现有实现是**固定十要素模板**：不管什么目标，都生成同构的 10 份文件，路径不随目标变化、不随表现变化。这是"训练路径不因人而异"的根因。

## What Changes

- 新增**两层生成策略**：骨架（阶段划分、顺序、每阶段目标与题量分布）一次生成并由用户确认；阶段内的训练项在进入该阶段时按实际表现再生成
- 路径以**结构化数据**保存（阶段 → 训练项），并支持**用户微调**与**确认后冻结**
- 新增**预算校验**：用户在澄清阶段确认的"周期 × 每周频次 × 每次时长"换算成总分钟预算，路径超预算必须被拒绝
- 训练项标注**题型**（记忆性 / 理解性 / 实践性）与**难度档位**，难度必须附带依据；运行中按真实表现校准
- 支持**覆盖模式**与**达成模式**两种目标类型，决定总量是否锁定
- 主视图采用**嵌套列表 + 进度条**，阶段与训练项、题型分布、进度一目了然
- 路径改动**保留版本**，不覆盖历史
- 沿用 ADR-0001：**AI 只产出内容与顺序，具体哪一天练由调度器计算**

### 关键取舍

| 选择 | 备选方案 | 放弃理由 |
|---|---|---|
| **两层生成**（骨架 + 阶段细节） | 一次生成全部细节 | 长周期细节必然失真：用户第 3 天暴露的薄弱点，不该等到第 30 天才响应；且前期信息不足 |
| **预算由规则算，超支直接拒绝** | 让模型自己估工作量 | 总量是可算的，算得出来的事不该交给概率；模型为显得完整天然倾向塞满内容 |
| **题型与难度随训练项一起生成** | 只生成题目，难度事后补 | 难度影响排期与调整策略，缺失就无法决定"该多练还是该降档" |
| **主视图用嵌套列表** | mermaid 流程图 | 训练场景的结构就是文档章节树；模型画图会与真实状态脱节（见 ADR-0009） |
| **覆盖模式与达成模式并存** | 单一模式 | 培训场景要求覆盖完整，自定目标要求达标即止，两者不能用一个规则表达（见 ADR-0011） |
| 本次不改 `trainer-generation` | 直接修改其"按十要素生成 10 份文件"的规格 | 十要素文件是留是废属于独立决策，且该 spec 正被 `goal-clarification-confirm` 修改，避免 delta 冲突 |

详见 `workspace/decisions/ADR-0009`、`ADR-0010`、`ADR-0011`。

## 非目标（Non-goals）

- **不做每日排期**：路径只给顺序与阶段，具体日期由调度器计算（ADR-0001）
- **不做十要素文件的去留决策**：留给后续 change（见下方"留给后续的问题"）
- 不做多支线 / 并行路径：第一版是**线性阶段 + 显式前置标记**，不做通用 DAG
- 不做训练项类型的全量覆盖：只做背诵 + 改错，复述/讲解后续补
- 不做路径的自动重排：任何改动由用户发起或确认
- 不做跨训练的路径迁移与复用
- 不引入向量检索与 embedding（沿用 ADR-0007）

## 原待决问题的处置（2026-09-20 更新）

| 问题 | 处置 | 依据 |
|---|---|---|
| 十要素模板生成的 10 份 md | **已决：降级为导出物**——结构化数据是唯一真相，md 由数据渲染，禁止反向写入 | `ADR-0017` |
| 基线诊断在新流程中的位置 | **已决：升级为「理解边缘定位」**，固定为独立一步，位置在选好来源之后、生成路径之前 | `ADR-0018` |
| 关键词白名单 | **暂缓**：先去留不定，但已确认它不影响基线设计（探测所需的知识点清单可只从来源切片与验收标准推导） | 待后续决策 |

### 由此产生的输入变化

路径生成的输入从两项变为**三项**：

```
已确认的目的（goal_json） + 可用的资料来源（sources） + 理解边缘定位结果（逐知识点三态）
```

其中第三项决定了"哪些跳过、哪些是教学重点、哪些需要前置铺垫"，是路径不浪费的前提。

## Capabilities

### New Capabilities

- `path-generation`: 训练路径生成——骨架生成与确认、阶段细节滚动生成、预算校验、题型与难度标注、版本管理、列表式进度展示

### Modified Capabilities

无。有意不改 `trainer-generation`，避免与进行中的 `goal-clarification-confirm` 在同一 spec 上产生 delta 冲突。

## Impact

- **代码**：`src/services/`（新增路径生成与预算校验服务）、`src/db/`（新增 `training_paths` / `path_stages` / `training_items` 表 + 迁移）、`src/ui/`（新增路径查看与微调页面）、`src/llm/`（新增用途 `path_skeleton` 与 `stage_items` + Schema）
- **数据**：新增三张表；训练项通过 `source_chunk_ids` 回指来源切片（依赖 `training-source-selection` 提供的表）
- **依赖**：无新增第三方依赖
- **API**：无（当前项目没有 API 层）
- **测试**：预算校验、阶段顺序与前置依赖、难度依据校验、版本比对的纯函数单测
- **证据**：路径总量与预算偏差、难度人工复核一致率、阶段解锁与完成比例——**待实测，当前标【待验证】**
