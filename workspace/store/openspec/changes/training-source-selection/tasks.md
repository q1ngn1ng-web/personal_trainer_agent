## 2. 解析与切片（纯函数优先）

- [ ] 2.1 实现 Markdown / txt 解析：读取文本并保留标题层级
  - 验收：单测断言 `heading_path` 形如 `第三章 > 3.2 虚拟语气`
- [ ] 2.2 实现 PDF 解析（选型见 ADR-0007，优先复用 `PythonProject16` 的方案）
  - 验收：对一份真实 PDF 解析成功并能输出 Markdown
- [ ] 2.2b 实现 Word（.docx）解析：按标题样式与段落层级转 Markdown
  - 验收：用 2 份真实 docx 讲义解析成功，标题层级正确
- [ ] 2.2c 实现 Excel（.xlsx）题库解析：识别题干 / 选项 / 正确答案 / 解析列，输出结构化题目
  - 验收：用 2 份真实题库表格解析成功；表头不规整时判失败并提示，不猜列含义
- [ ] 2.3 实现切片函数：按标题层级 + 段落边界，超长时递归切分并保留标题前缀
  - 验收：单测覆盖「不跨知识点」「超长切分后前缀保留」两种情况
- [ ] 2.4 解析失败路径：写 `parse_status=failed`、保留原始记录、不阻塞其他来源
  - 验收：故意传入一个损坏文件，流程不中断且状态为 failed

## 3. 来源服务

- [ ] 3.1 新增来源服务：登记来源（三类）、触发解析、写入切片与索引
  - 验收：三种来源各跑一遍都能在库里看到切片
- [ ] 3.2 实现校验值计算与增量重建：内容未变则跳过解析
  - 验收：同一文件导入两次，第二次日志显示跳过解析
- [ ] 3.3 实现影响面计算：切片的新增 / 删除 / 修改清单 + 受影响训练项清单
  - 验收：修改资料后能看到清单，且不自动删除任何训练项
- [ ] 3.4 实现候选切片检索（FTS5），供路径阶段使用
  - 验收：给定关键词能返回按相关度排序的切片，且不产生 LLM 调用

## 4b. 网络来源（URL 抓取与快照）

- [ ] 4b.1 实现抓取：输入 URL → 取回 HTML → 记录 HTTP 状态与 `fetched_at`
  - 验收：抓一个可访问页面成功，抓一个不存在的域名得到明确失败原因
- [ ] 4b.2 实现正文抽取：剥离导航 / 页脚 / 脚本，只保留主体并转 Markdown
  - 验收：单测用一份含导航与脚本的样本，断言输出不含导航文本
- [ ] 4b.3 保存快照：`snapshot_text` + `origin_url` + `fetched_at` + `checksum`
  - 验收：抓取后库中能看到快照与时间戳，界面展示原始链接与快照时间
- [ ] 4b.4 失败显式化：DNS / 超时 / 403 / 人机校验 / 正文为空（单页应用）
  - 验收：用今天调研中真实失败的三个页面类型各测一次，均得到明确失败提示而非空来源
- [ ] 4b.5 手动刷新快照：重新抓取后走增量重建与影响面流程
  - 验收：改动页面后刷新，能看到切片变更清单与受影响训练项
- [ ] 4b.6 边界约束：不跟随页面链接、不做定时重抓、不绕过反爬
  - 验收：代码检查 + 文档说明；抓取实现中不存在递归抓链接的逻辑
