# adaptive-learning-loop · 自适应学习闭环（backlog，面试后实施）

> 状态：**仅提案，未实施**（用户决策 2026-11-16/18：先登记完整设计，面试前不动主链）。
> 本 change **合并并取代** `adaptive-practice-composition`（其构想全部纳入，git 历史留档）。
> 框架：assessment-driven instruction（以测促学、测什么补什么）——测量侧已上线（系统判分 + 规则错因全量落库），本 change 补齐「暴露缺口 → 定向补材 → 回炉再测」的后半环。

## Why

当前系统是一个完整但**单环**的测练闭环：出题判分（锚定用户资料）→ 错因落库 → 达标判定。三个体验缺口：

1. **缺口不补**：probe 暴露的 unreached 知识点、连续错因聚集的薄弱点，系统只会"再练原题"，没有定向的内容补给——资料没覆盖的地方永远缺；
2. **错题不回流日常**：错题只通过达标重练/测验补练/深度解析三条间接路径起作用，当日训练清单里不会出现"这道题你上次错了，再来一遍"；
3. **不能提前练**：今天状态好想多练，系统不允许（today 只显示到期且前序未完成的最早一轮）。

## What Changes（三个能力 + 一条触发总线）

- **定向补材（corpus augmentation）**：按触发规则在缺口上生成**微型补充资料**，作为一等 source 落库（`type='ai_generated'`，schema 已预留）→ 照常切片进 FTS → 题目照样回指它。**绝不导入时全量补全**。
- **错题回炉 + 同题巩固**：当日清单在主轮次之外附加回炉题（带上限，复用 question_bank 存量题，不重新生成）；冷却期外原题低概率混入（日常原题巩固 + 测验变式检验的分工）。
- **提前训练**：显式"提前练下一轮"——只提前提供作答机会，不改 due_date/锚定排期/达标口径。
- **触发总线（宁缺毋滥）**：①probe 显示 unreached；②同一知识点错因聚集 ≥2 次；③heading_path 覆盖分析发现空洞。

### 两条不可破的红线（从设计讨论沉淀）

| 红线 | 内容 | 为什么 |
| --- | --- | --- |
| **效度锚定** | 补充必须为**原始资料的掌握**服务（定向于测验暴露的缺口，补完按原标准再测）；禁止全面重写知识域 | 若考的是 AI 扩写的知识域，测的就不是"用户带来的资料"——测验效度崩塌 |
| **质量门槛** | 补材生成锚定相邻已验证切片（不凭空写）；显式标注「AI 补充」；用户可审阅/可关闭 | 学习场景的错误资料是毒药（用户会背下来） |

## 2026-11-20 设计决策（用户拍板）

1. **资料更新 = 版本化**：更新产生新版本，旧引用继续指旧版本，新训练拿新版（与 training_paths 的 version/superseded 哲学同构）。
2. **训练模式创建后不可变**（anchored/systemic 二选一，锁定）；已生成内容在模式下的准入由创建时模式决定。
3. **渐进式覆盖重立项**：导入时只做「知识点提取 + 第一轮题」；每轮结束后由浅入深后台生成下一轮题、覆盖更多知识点；第 5 轮结束时覆盖率 100%。**待拍板的衍生矛盾**：后期引入的知识点暴露次数少于核心点（引入即 5 轮 vs 第 3 轮引入只剩 3 轮）——暴露契约需定：核心点≈5 次 / 外围点≥2 次 / 每点≥1 次？（定稿后进排期设计）
4. **知识点提取升级**：从「标题路径规则切分」（build_knowledge_points 现状）升级为**类型化 LLM 提取**（type/core/prerequisites/verbatim/chunk_refs），chunk 溯由规则层强校验；类型学演示稿见 for-work 2026-11-20 讨论。
