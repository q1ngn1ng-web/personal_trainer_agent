# learner-memory-and-grading · 设计

## D1 判分模型：从二态到可解释分数

### 数据形态

每道题绑定一份**结构化要点清单**（取代自由文本 `reference_answer`）：

```
points: [
  { id: "p1", text: "Redis 单线程处理命令",      weight: 2, required: true  },
  { id: "p2", text: "单线程避免锁竞争",          weight: 1, required: false },
  { id: "p3", text: "6.0 引入多线程 IO",         weight: 1, required: false }
]
```

判分时对每条要点给出四态：`命中` / `部分命中` / `错误` / `缺失`。

### 计分

| 指标 | 公式 | 作用 |
|---|---|---|
| 覆盖率 Coverage | Σ(命中权重 + 0.5 × 部分命中权重) ÷ Σ总权重 | 答全了没有 |
| 正确性 Correctness | 回答涉及的要点中，`错误` 占比扣分 | 答对了没有——**说反了比没说更糟** |
| 必答项 | `required` 要点未被命中 | 一票否决，不被权重稀释 |
| 最终完整度 | Coverage × Correctness | 0—1 的连续分数 |

只算覆盖率会漏掉"把三点全念一遍但说反一点"的情况；只算要点个数（3 个答 2 个 = 66.7%）会掩盖"漏掉的正是命门"。

### 输出

分数 + **缺失要点列表** + **错误要点列表**。可解释性优先于分数本身：用户需要的是"你漏了 C、B 说反了"。

## D2 题型分流

| 题型 | 判分方式 | 理由 |
|---|---|---|
| choice（选择） | 确定性比对，不调模型 | 有标准答案 |
| fill（填空） | 归一化后精确比对（同义答案暂不处理） | 同上，先不做语义等价 |
| qa（问答/背诵） | 要点覆盖率 × 正确性 | 自由表述，只能语义判定 |

选择题的**干扰项 MUST 来自同一资料片段**，否则会出现资料外的选项，用户可靠排除法作答。

## D3 三层记忆

| 层 | 载体 | 性质 |
|---|---|---|
| L1 事实层 | `practice_attempts`（升级：`score`、要点级明细） | 唯一真相源，可精确查询 |
| L2 派生层 | 薄弱点画像（SQL 聚合，可落表可现算） | 全部确定性计算，**不调 LLM** |
| L3 上下文层 | `memory_service` 渲染的紧凑摘要 | 注入 prompt 的那一段 |

### L3 渲染示例

```
【学习者画像】近 30 天：Redis 持久化 3 次未达标（2 次混淆 RDB/AOF，1 次漏"fork 写时复制"）
【题型分布】选择题失误率 40%，问答 15% → 本轮已提高选择题占比
【本场进度】已完成 8/20（问答 5、选择 3），均分 72
【当前题】上一题错在"主从复制的异步性"
```

关键点：**不是压缩原始对话，而是一开始就不产生原始对话**。信息一直在库里，注入时按需渲染。

## D4 自适应出题

薄弱点驱动，**下一场生效**（本场总结出薄弱项 → 下一场调整配比），因为一场测验的结论要结束后才成立。

输入是 L2 的题型失误分布与知识点掌握度；输出是下一场的题型配比与知识点的出题权重。

## D5 数据模型变更

| 变更 | 说明 |
|---|---|
| `question_bank.question_type` | 新增，choice / fill / qa，**不复用 `item_type`**（后者是训练项类型 memory/comprehension/practice，语义不同） |
| `question_bank.options` | 新增，存全部选项并标记正确项 |
| `question_points` | 新增表，存结构化要点清单（题号 / 要点 / 权重 / 是否必答） |
| `practice_attempts.score` | 新增，0—1 连续分 |
| `practice_attempts.point_results` | 新增，要点级判定明细（JSON） |
| `assessment_items.question_type` | 新增，判分分流依据 |

## D6 可测指标

| 指标 | 口径 |
|---|---|
| 上下文规模 | 整场评分的 prompt token 数 vs 塞入全部原始作答的 token 数 |
| 记忆准确性 | "用户错过哪些题"这类查询的准确率（确定性查询应为 100%） |
| 跨 30 天一致性 | 第 30 天仍能正确引用第 1 天的错题 |
| 判分稳定性 | 同一份作答重复判分，分数的波动范围 |
| 判分一致性 | 与人工标注样本的吻合度 |
| 分流收益 | 客观题判分的 token 消耗（应为 0） |
