# learner-memory Specification

## ADDED Requirements

### Requirement: 记忆以结构化事实为唯一真相源

系统 SHALL 把每次作答的结构化记录（题目、知识点、题型、分数、要点级判定、时间）
作为学习者记忆的唯一真相源，并 SHALL 支持精确查询。
系统 MUST NOT 以向量检索或自然语言摘要作为事实层。

#### Scenario: 精确回答错题查询

- **WHEN** 系统需要回答"用户在某个知识点上错过哪些题"
- **THEN** 结果由结构化记录精确查询得出，MUST NOT 依赖近似召回

### Requirement: 薄弱点画像由确定性计算得出

系统 SHALL 基于结构化记录计算薄弱点画像，至少包含：知识点掌握度、稳定通过率、
高频错误类型、题型失误分布。该计算 MUST NOT 调用大模型。

#### Scenario: 生成画像不产生模型调用

- **WHEN** 系统生成或刷新学习者画像
- **THEN** 过程中不产生任何 LLM 调用

### Requirement: 上下文按需渲染且可量化

系统 SHALL 在需要时把事实与统计渲染为紧凑上下文注入提示词，
MUST NOT 把跨度达数十天的原始作答全集直接放入上下文。

#### Scenario: 渲染紧凑上下文

- **WHEN** 整场评分或生成解析需要历史信息
- **THEN** 系统渲染包含学习者画像、题型分布、本场进度、当前题背景的紧凑摘要

#### Scenario: 上下文规模可对比

- **WHEN** 完成一次整场评分
- **THEN** 系统可给出"渲染后 token 数"与"原始作答 token 数"的对比

### Requirement: 记忆独立于会话生命周期

系统 SHALL 保证学习者记忆持久化于存储层，与进程或会话无关；
会话重启后系统 MUST 能重建等价上下文。

#### Scenario: 重启后仍能引用早期错题

- **WHEN** 距离某题作答已过去数十天且服务重启过
- **THEN** 系统仍能正确引用该题的判分结果与错误要点

### Requirement: 每道错题必须记录结构化错因

系统 SHALL 为每次作答中的错误要点记录错因，错因 MUST 取自固定枚举
（记忆缺失 / 概念混淆 / 表达不完整 / 关键遗漏），MUST NOT 仅以自由文本形式保存。
错因 SHALL 能由要点判定确定性推导，推导过程 MUST NOT 调用大模型。

#### Scenario: 从要点判定推导错因

- **WHEN** 某条要点被判为 `missing`
- **THEN** 该要点记录错因为「记忆缺失」
- **THEN** 本次推导不产生任何 LLM 调用

#### Scenario: 错因可聚合

- **WHEN** 系统统计某知识点的高频错因
- **THEN** 结果按错因枚举聚合，能够回答"这个错因出现过几次"

### Requirement: 错题分析由用户决定是否开启

系统 SHALL 提供"是否开启 LLM 错题分析"的开关，默认关闭。
关闭时 MUST NOT 为错题调用模型；开启时才对错题生成分析，
分析结果 MUST 单独存储，MUST NOT 覆盖规则推导出的错因。

#### Scenario: 开关关闭

- **WHEN** 用户未开启错题分析
- **THEN** 系统不产生错题分析的 LLM 调用
- **THEN** 该题仍保留规则推导出的错因

#### Scenario: 开关开启

- **WHEN** 用户开启了错题分析并答错一道题
- **THEN** 系统为该题生成分析文本并单独存储

### Requirement: 评价本次作答时要注入历史错因

系统 SHALL 在评价本次作答时，注入该知识点最近若干次同类错因的摘要，
使评价具备时间纵深。该摘要 SHALL 由结构化记录渲染，MUST NOT 依赖对话历史。

#### Scenario: 同一错因反复出现

- **WHEN** 某知识点近期多次因同一错因出错，本次再次出错
- **THEN** 评价中指出该错因反复出现，并给出出现次数
