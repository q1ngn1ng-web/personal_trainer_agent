# answer-grading Specification

## ADDED Requirements

### Requirement: 题目必须携带结构化要点清单

系统 SHALL 为每道主观题存储结构化要点清单，每条要点包含要点文本、权重与是否必答。
要点清单 MUST 随题目固化，MUST NOT 在判分时由模型临时生成。

#### Scenario: 要点随题目固化

- **WHEN** 系统生成或导入一道主观题
- **THEN** 该题同时产生一份带权重的要点清单并落库
- **THEN** 后续判分复用同一份清单

#### Scenario: 缺失要点清单时拒绝判分

- **WHEN** 一道题没有要点清单
- **THEN** 系统 MUST NOT 用模型自由发挥的方式给出分数

### Requirement: 判分必须按题型分流

系统 SHALL 依据 `question_type` 选择判分方式：选择题与填空题走确定性判分，
主观题走要点评分。客观题的判分 MUST NOT 调用大模型。

#### Scenario: 选择题确定性判分

- **WHEN** 用户提交选择题答案
- **THEN** 系统直接比对标准答案得出结果
- **THEN** 本次判分不产生任何 LLM 调用

#### Scenario: 填空题不处理同义答案

- **WHEN** 用户填写的答案与标准答案语义相同但文字不同
- **THEN** 本期系统判为不通过（同义答案处理不在本期范围）

### Requirement: 主观题按覆盖率与正确性给分并可解释

系统 SHALL 对每条要点给出命中 / 部分命中 / 错误 / 缺失四种判定，
并据此产出覆盖率与正确性；最终完整度 SHALL 为两者之积。
判分结果 MUST 包含缺失要点列表与错误要点列表。

#### Scenario: 部分覆盖

- **WHEN** 题目有 A、B、C 三条要点，用户只回答了 A 与 B 且均正确
- **THEN** 覆盖率为三分之二
- **THEN** 判分结果指出缺失要点为 C

#### Scenario: 答全但说反

- **WHEN** 用户覆盖了全部三条要点，但其中一条表述错误
- **THEN** 最终完整度低于"只答对两条"的情形

### Requirement: 必答要点缺失时一票否决

系统 SHALL 将标记为必答的要点作为硬门槛：必答要点未被命中时，
该题 MUST 判为不通过，且 MUST NOT 因其他要点得分而被拉回。

#### Scenario: 缺必答项

- **WHEN** 用户答对了多条高权重要点，但缺少一条必答要点
- **THEN** 该题判为不通过

### Requirement: 选择题干扰项必须来自同一资料片段

系统 SHALL 从题目所属资料片段中选取干扰项，MUST NOT 引入资料之外的内容。

#### Scenario: 干扰项可溯源

- **WHEN** 系统生成一道选择题
- **THEN** 每个选项都能在题目关联的资料切片中找到依据
