# learner-memory-and-grading · 学习者记忆与可解释判分

## Why

训练闭环的"执行—反馈"段已经打通，但**评测与记忆这两块还是空的**，导致三件事都做不了：

1. **判分没有刻度**：`assessment_items.verdict` 只有 `pass` / `fail` 两态，`reference_answer` 是一段自由文本，大模型每次自由发挥。结果是——判分不稳定（同一份作答两次可能不同）、不可解释（只知道错，不知道错在哪）、无法回答"能得几分"。
2. **没有记忆，30 天跨度接不上**：一次训练计划跨越 30 天，agent 必须知道"这道题错过几次""在那个知识点上一直不稳"。现在每次都要从数据库现查现拼，没有薄弱点画像，也没有统一的上下文组装口子。
3. **题型单一，浪费了确定性判分的机会**：目前只有开放式问答，所有题都走 LLM 判分。而选择题、填空题本身有确定答案，本可以零 token、零延迟、100% 稳定地判掉。

同时 `assessments.score` / `passed` 字段一直是空的——"根据整场作答给出评分"这条链路原本就在设计里，只是没实现。

## What Changes

- **判分升级**：题目的参考答案从自由文本升级为**结构化要点清单**（要点文本 + 权重 + 是否必答）；判分对每条要点给出四态结论；输出分数 + 缺失要点 + 错误要点
- **题型引入**：`question_bank` 新增 `question_type`（choice / fill / qa）与 `options` 字段；**客观题走确定性判分，主观题才走要点评分**
- **记忆分层**：事实层（`practice_attempts` 升级为带分数的唯一真相源）+ 派生层（薄弱点画像，纯 SQL 计算）+ 上下文层（`memory_service` 按需渲染紧凑摘要注入 prompt）
- **错因记录**：每道错题按要点级判定推导结构化错因（记忆缺失 / 概念混淆 / 表达不完整 / 审题偏差），存下来用于聚合
- **可选错题分析**：用户自行决定是否开启 LLM 深入分析（开关可关，控制成本与隐私）；关闭时错因仍由规则推导
- **长期记忆参与评价**：LLM 评价本次作答时，注入"过去若干次同类错因"，让评价有历史纵深
- **自适应出题**：下一场测验的题型配比按上一场暴露的薄弱项调整
- **整场评分**：测验结束后聚合每题结果，产出总分 + 知识点掌握 + 薄弱点 + 下一步建议
- **按需解析**：用户在某题请求解析时才生成，且必须引用资料来源原文片段；该行为记录为学习信号

### 关键取舍

| 选择 | 备选方案 | 放弃理由 |
|---|---|---|
| **不引入记忆框架**（mem0 / Zep / LangChain Memory） | 用现成框架做"长期记忆" | 本项目 95% 的记忆是结构化状态（哪题错、得分多少、何时答的），必须精确查询；框架面向的是对话记忆，存储为向量或自然语言摘要，查询是近似的，属于能力错配。`practice_attempts` 已是现成的真相源 |
| **记忆 = 持久化状态，不是长会话** | 让一个 agent 会话常驻 30 天 | 常驻会话意味着服务有状态：不能重启、不能水平扩展、换模型即丢上下文。正确做法是服务无状态，每次从数据库重建上下文 |
| **客观题不走大模型** | 统一走 LLM 判分，实现简单 | 选择题/填空题有确定答案，走模型是白付 token、白等延迟、还把 100% 的确定性换成随机性 |
| **要点清单随题固化** | 每次判分时由 LLM 现抽要点 | 现抽的结果每次不同，分数会漂；判分锚点必须稳定（与评测集用 `gold_anchors` 同理） |
| **上下文"渲染"而非"压缩"** | 把原始对话压缩成摘要 | 从结构化事实直接渲染，既不丢信息也不花额外调用；压缩原始对话则是先浪费再补救 |
| **错因用分类枚举而非自由文本** | 让模型随手写一段错因 | 自由文本没法聚合，"这个错因出现过几次"就答不出来；枚举还能由规则从要点判定直接推导，不花模型 |
| **错题分析做成用户开关** | 每次都自动调模型分析 | 每道错题都分析会显著推高成本，且用户未必要；默认不打扰，开启后才深入分析 |
