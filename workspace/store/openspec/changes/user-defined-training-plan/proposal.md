# user-defined-training-plan · 用户自定义训练计划（总时长×次数，AI 协调覆盖，总测验定通过）

> 状态：**仅提案，未实施**。本文件为自包含交接文档，供实施会话执行。
> 来源：2026-11-22 用户产品决策：澄清阶段就要让用户看到并自定义**总时长与训练次数**
> （例：两周之内训练三次），由 AI 协调每次训练覆盖的知识点；训练完成以**总测验**判定，
> 不通过则重新来。**本 change 实质修订 ADR-0021（固定五轮锚定创建日）**——实施时须写新 ADR。

## Why

现模型（ADR-0021）：五轮固定间隔锚定创建日、**每轮覆盖全部训练项**、完成条件=必修覆盖 100%
+ 最近测验通过。三个与用户预期的偏差：

1. **投入参数无家可归**：用户能投入多久（总时长）、想练几次，系统既不问也不个性化
   （澄清提示词第 6/7 条明令禁问，路径用内置默认 2 周×5 天×30 分钟）——对"两周三次"这种
   明确约束的用户，系统给的是同一副骨架；
2. **每轮全覆盖导致负载尖峰**：12 题在第 1/3/7/15/30 天全量脉冲（评审已确认的缺陷）；
   用户期望的是"每次训练覆盖一部分知识点，AI 协调"；
3. **完成判定分散**：连续 2 次通过/每 14 天测验/必修覆盖三个口径叠着，用户心智里只有一件事：
   "最后考一下，过了就算完成"。

## What Changes

**A. 澄清阶段收集投入参数（UI 收集，不走 LLM 对话）**

- 澄清步展示"训练节奏"卡片：**总时长**（周数，默认 2，范围 1-8）× **训练次数**（默认 3，范围 2-6），
  用户可改——以 UI 控件收集（不是聊天追问），写入 goal 快照两个字段
  `horizon_days` / `session_count`，`field_sources` 标 `user_input`；
- 提示词修订：第 6/7 条改为「周期/时长/次数由界面控件收集，**对话中严禁追问**；
  若用户在对话中主动提及，仅保留在 content」——禁止的是 LLM 追问，不是收集本身；
- AI 给参考建议：卡片上按知识点数量与目标等级显示推荐值（如 12 个知识点+「能讲清」
  → 建议 3-5 次；次数×容量 < 需要的覆盖时警告"偏少，建议增加次数或延长时间"）。

**B. 排期模型 v2：N 次训练，AI 协调覆盖（纯规则分配，LLM 可选重排）**

- 会话日期：N 次在 horizon_days 内**近似均匀摊开**（间隔=horizon/N，可被
  performance-driven-scheduling 的阶梯微调）；
- **覆盖分配算法（规则层，确定性）**：按阶段顺序把训练项分给各次会话
  （新知优先靠前、每项最少出现 2 次：首次学习 + 至少一次复习；错过的项累计顺延进下一次）；
  LLM 仅可在生成时对分配做"叙述性微调建议"，**分配本身 MUST 是纯函数**（可复现可测试）；
- plan_items 语义调整：`round_index` → `session_index`（1..N），预生成保留（UNIQUE 幂等）；
- **总测验（完成门）**：最后一次会话后触发**终测**（assessments，trigger='final'，覆盖全部必修项）；
  通过 → trainings.status='completed'；不通过 → **重新来**：按剩余 horizon 与未过项重新生成
  计划（沿用已达标项的记录），horizon 用尽则提示用户延长或接受"未完成"归档；
- per-item 连续 2 次通过（mastery）**保留**——它是 AI 分配复习优先级的输入与渐进反馈，
  但**整体完成由终测单独把关**。

**C. 与既有 backlog 的收编关系（实施顺序约束）**

| 对象 | 关系 |
| --- | --- |
| performance-driven-scheduling | 阶梯模型**被本 change 吸收**：五档 ladder → 会话内自适应（pass 拉开同题复习、fail 插入下次会话）；实施顺序：**先本 change 定骨架，后移植阶梯** |
| adaptive-practice-composition | 回炉/提前练语义在会话制下重新表述（回炉=插入下次会话清单）；收编进本 change 任务 1.4 |
| coach-memory-three-layers | 不受影响（会话小结按"当日"聚合，与 session_index 正交）；daily_minutes_target 偏好喂本 change 的单次容量 |
| graded attempt / 判分 / 达标规则 | **零变化**（本 change 只动排期与完成门） |

### 关键取舍

| 选择 | 备选 | 放弃理由 |
| --- | --- | --- |
| UI 控件收集投入参数 | 澄清对话追问 | 澄清管"学什么/学到什么程度"，投入是路径参数；控件一步到位不打断对话 |
| 覆盖分配纯函数 | LLM 直接分配知识点 | 排期必须可复现可测试（ADR-0001 边界）；LLM 只做建议层 |
| 每项最少出现 2 次 | 每项只出现 1 次 | "能讲清"级至少需要 学习+复习 两次接触；次数不够时 UI 警告而非静默降级 |
| 终测单独把关完成 | 沿用"最近测验通过" | 用户心智模型是"最后考一下"；终测覆盖全部必修，与 14 天小测职责分离 |
| horizon 用尽 → 显式归档 | 自动无限延长 | 诚实边界：投入约束是用户自己定的，系统提示选择而非悄悄违约 |

## 非目标（Non-goals）

- 不改判分公式/要点评分/达标 streak 语义
- 不做逐日精确日历（会话内哪天练仍由今日查询语义决定）
- 不做 LLM 参与排期决策（分配是纯函数；LLM 只产建议）
- 不迁移存量训练（老训练按旧模型跑完，schedule_mode 区分）
