# user-defined-training-plan · 设计

## D1 为什么投入参数收进澄清步（UI 收集而非对话）

澄清的对话轮次只服务"学什么/学到什么程度"的结构化；投入参数（总时长/次数）是两个
封闭枚举控件，UI 一步收集零误解成本。放澄清步（而非路径步）是因为用户心智里
"定目标时就该说清打算投入多少"——且 goal 快照统一存证（field_sources=user_input）。
提示词只保留"对话中严禁追问"（防止 LLM 越界），收集职责移交 UI。

## D2 覆盖分配为什么是纯函数

ADR-0001 边界：LLM 管语义、规则管状态。分配=约束求解（items×最少接触 ≤ N×容量、
新知靠前、顺延进位），确定性输出才可测试；LLM 的价值在"建议推荐次数"与
"叙述分配理由"，不在分配本身。若未来要 LLM 参与重排，输出也 MUST 经规则校验。

## D3 最少接触 2 次的依据

目标等级「能讲清」的语义 = 能输出性（output）训练，一次学习不构成输出能力；
学习+至少一次复习是下限。次数×容量 < 需求时 UI 警告（0.2 决策定是否硬禁止）——
系统不静默降低标准。

## D4 终测完成门与既有达标的关系

per-item 连续 2 次通过保留：它驱动 AI 分配（弱项回炉）与渐进反馈（记忆/解析消费）；
**整体完成**改由终测单独判定（全部必修项、trigger='final'）——回应"用户心智里
只有最后考一下"。不过→重排：已达标项不重练（保留 streak 记录），未达标项
按剩余 horizon 重新分配；horizon 用尽→显式归档让用户选，不静默违约。

## D5 与 performance-driven-scheduling 的收编

阶梯（pass 拉开/fail 归零）在本模型下落为**会话内自适应**：session_index 固定，
同题在会话间的复现由上次表现决定（fail→下会话必现+优先）。实施顺序：
先本 change（骨架），后移植阶梯（微调语义）——避免两套"重练"语义并存。

## D6 回滚

schedule_mode 隔离存量；revert 提交即可，goal_json 新字段对旧代码无害（额外键）。
