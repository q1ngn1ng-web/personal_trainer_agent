# grading-consistency · 判分一致性治理

> 状态：进行中（代码与实测已落地 2026-11-02；人工一致率标注待执行）。

## Why

判分是本系统"客观表现唯一事实源"的入口，但模型的逐条四态判定是概率输出。实测（2026-11-02，阿里云兼容端点 `deepseek-v4.1-flash`，样本 plan_item #235、同一作答重判 5 次，`scripts/eval_grading_consistency.py`）：

- 温度 0.2（旧行为）：**3 种判定组合**、得分 0.551-0.9286、通过判定 fail×4 / **pass×1**——同一作答的重判能翻转达标；
- 温度 0.0：仍有 **4 种组合**——波动来自服务端非确定性，**无法靠温度消除**。

达标判定（≥0.8 且连续 2 次）与下游记忆聚合（薄弱点画像、错因分布、题型配比）都建立在逐次判分之上；判分不稳定 = 客观记录被噪声污染。

## What Changes

- **判分用途温度降为 0**：`client.PURPOSE_TEMPERATURES = {"quiz_grade": 0.0}`（`temperature_for()`），消除客户端采样噪声——实测证明它不足以单独解决问题，但方向正确、零成本。
- **新增幂等判分缓存（正解）**：`grading_cache` 表 + `src/services/grading_cache.py`。同一（模型, prompt 版本, 题目, 参考答案, 要点清单, 作答）的模型判定**判一次、存一次、永久复用**——重判逐字复现（由集成测试钉死）、零重复调用；缓存存模型语义意见，分数与达标仍由规则层实时计算。
- `answer_service._grade_answer` 与 `quiz_service.grade_with_llm` 两处判分调用接入缓存。
- 自一致性实验脚本与证据归档（`workspace/evidence/20261029-时间成本基准.md` 追加节）。

### 关键取舍

| 选择 | 备选方案 | 放弃理由 |
| --- | --- | --- |
| 幂等缓存为正解 | 仅调温度 / 多数投票 | 实测温度 0 不消除服务端非确定性；投票 = 3 倍 token 且仍非确定 |
| 缓存存模型意见、分数实时算 | 缓存最终分数 | 规则层判分口径升级不应被历史分数锁死 |
| 记忆背景不进缓存键 | 进键 | 口径约定背景只帮理解措辞不改判定；进键会让作答历史增长打散缓存 |
| 缓存键含模型与 prompt 版本 | 只按题+作答 | 换模型或升级 prompt 应重新判分 |

## Impact

- 新表 `grading_cache`（tables.sql + migrate + `test_db_schema.py` 守卫 34 表）
- `quiz_grade` 用途温度 0；其余用途温度不变
- 判分口径、达标规则、降级路径均不变
