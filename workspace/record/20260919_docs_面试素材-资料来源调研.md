# 20260919 · docs · 新建面试素材目录与资料来源竞品调研

## 变更摘要

新建 `workspace/面试/` 目录，存放竞品调研、差异化说明与技术选型依据；首篇覆盖「资料来源与知识导入」这一环节。

### 为什么需要这个目录

此前调研结论散落在 `proposal.md`、`ADR` 与聊天记录里，没有统一去处，也没有统一的证据规则。
结果就是分不清哪些结论是实测过的、哪些只是"看起来有道理"的推测，而面试官恰恰会追问这一点。

## 产出

| 文件 | 内容 |
|---|---|
| `workspace/面试/README.md` | 写作规则（结论分 `【公开信息】` / `【推测】` / `【已实测】` 三档）+ 目录 |
| `workspace/面试/01-资料来源与知识导入.md` | 四类竞品做法、五条共性规律、差异点强弱判断、技术选型与放弃理由、四道追问预案、待验证清单 |
| `AGENTS.md` | 目录约定新增 `workspace/面试/` 一行 |

### 文档的核心结论

1. **资料来源不是差异化点，是入场券**——NotebookLM、Quizlet、Dify 都能做，拼的是"能不能用"
2. **真正的差异在资料之后**：资料 → 训练项 → 排期 → 评测 → 达标 → 复盘，同类产品各覆盖一段
3. **第一版不上向量库**：个人场景切片量在数百级，SQLite FTS5 够用；ADR-0002 的触发条件尚未满足

### 明确写下的"不要这么说"

文档里专门列了三条会被反驳的说法（"我做了个 RAG 学习助手"、"优势是引用可追溯"、"支持 PDF/Word/Excel 导入"），
避免面试时把通用能力当成差异化讲。

## 影响范围

- 纯文档，无代码改动
- 建立了"面试材料也要标证据档位"的规则：只有 `【已实测】` 的结论可以作为强主张
- 产出一份待验证清单（试用 NotebookLM / Quizlet、跑资料解析统计、FTS5 与 embedding 对照）
