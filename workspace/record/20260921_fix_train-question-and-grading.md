# 20260921 · fix · 训练改为「系统出题 + 用户作答 + 系统判分」

## 变更摘要

用户报了一个**逻辑错误**：点进今日训练，看到的只是训练项的**标题**（如"RDB 快照时修改数据过程深度理解"），
然后系统问"有没有答对"——**既没有具体题目，也没有填空的地方，而且把判对判错交给用户自己**。
这与项目根上的原则（ADR-0015：客观表现不能靠自评；测验的设计初衷就是防止"自我催眠"）是矛盾的。

本轮按用户要求改成：

1. **系统出题**：每道训练题由系统生成（依据资料片段 + 轮次难度），落库到 `plan_items.question` / `reference_answer`；
2. **用户作答**：任务卡上给出作答框；
3. **系统判分**：提交后由模型判分（口径与测验一致，只出 pass / fail），结果写进 `practice_attempts`，
   连续 2 次通过 → 达标；
4. **撤掉"✓ 答对 / ✗ 答错"自评按钮**。只保留一个"只标记练过"的次要入口（不计入客观表现）；
5. **判分不可用时不伪造对错**：答案照存、标记练过，但**不写客观记录**，页面显示参考答案让用户自行核对。

> 例外（后置）：题目在**第三方题库**（如 LeetCode）且对方没有 API 时，系统只能安排任务、用户自己核对结果。
> 用户明确说"这个功能后面再开放"，本轮不做，代码里在 `answer_service` 顶部写明。

## 关键实现细节

1. **题目挂在一轮上**：一条计划项 = 一道题（同一知识点的第 1 轮与第 5 轮是两道不同的题），
   轮次越靠后题目越难（第 1 轮回忆、第 2-3 轮应用辨析、第 4-5 轮综合表达）。
2. **出题懒生成**：只在用户真正打开那道题时生成并落库，不在排期时一次性生成 5×N 道题（省成本，也避免早期题目作废）。
3. **判分口径与测验一致**：复用 `quiz_grade` 用途，只出 `pass` / `fail`，不做"部分正确"。
4. **不伪造客观数据**：判分失败时 `graded_by='unavailable'`，`practice_attempts` 不落行——
   这是审计 M5（"基础设施故障被当成答错"）那条教训的继续。

## 影响范围

- **行为**：任务卡从"标题 + 自评对错"变成"**题目 + 作答 + 系统判分**"；判分不可用时明确标注不计入客观表现
- **数据**：`plan_items` 加列（轻量迁移）；`practice_attempts.source` 用 `llm` 表示"模型判分的日常作答"
- **已知限制**：`item_key = sha1(training_id + 知识点 + 规范化标题)`，**同一知识点下标题完全相同的两道题会被合并成一道**
  （当前训练 50 的 19 个训练项里有 2 组同题重名，因此计划项是 17 道）——如果确实需要区分，需要改键规则
- **未做**：第三方题库（外部题）的自评入口、作答耗时记录、题目难度的人工复核
