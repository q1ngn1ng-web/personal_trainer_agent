# 20260920 · chore · ADR-0020 个人版与企业版用 profile 开关承载

## 变更摘要

修正 ADR-0019 中"企业版是个人版超集"的不准确表述，并确定两个版本的功能差异用 `profile` 开关承载，而不是开 git 分支。

### 触发

用户提出：企业版的颗粒度没有个人版细，个人版要删一些东西；企业版可以去掉 URL 来源与 AI 自动生成资料，因为企业一般用内部文档。因此倾向于开两个分支。

### 记录的核心内容

1. **承认功能集不同**：企业版确实会砍掉 URL 来源与 AI 生成资料，因此不是超集，而是**有交集但不相等**
2. **但功能差异不等于代码分叉**。判断标准：差异是"要不要用某个能力"（用开关），还是"同一能力有两套实现"（才需分叉）
3. 逐项核对后，URL 来源、AI 生成、默认模式、颗粒度、鉴权**全部属于第一类**
4. 共用部分（解析、切片、FTS5、评测、调度、Harness、路径生成）占绝大部分代码量，开分支会导致复制或反复 cherry-pick
5. **引入 `profile`（personal / enterprise）**，差异集中在配置与策略层；**禁用不等于删除**
6. 开关必须登记在 ADR 清单里，禁止在业务代码散落隐式 profile 判断
7. **真正需要分叉的条件**：同一能力需要两套实现并长期并行维护（私有化部署、对接企业统一身份、数据不出内网）

### 开关清单

| 开关 | personal | enterprise |
|---|---|---|
| 资料类型 `web_url` | 启用 | 禁用 |
| 资料类型 `ai_generated` | 启用 | 禁用 |
| 默认训练模式 | 达成 | 覆盖 |
| 路径颗粒度 | 细 | 粗 |
| 鉴权与角色 | 关闭 | 启用 |
| 企业指标报表 | 不展示（保留原始数据） | 展示 |
