# 20261102 feat 判分一致性治理（温度确定化 + 幂等判分缓存）

> 类型：feat｜关联 OpenSpec change：`grading-consistency`

## 变更摘要

消除"同题同答重判结果漂移"的判分链路漏洞。实测（2026-11-02，阿里云免费端点）：
温度 0.2 下同题同答重判 5 次出现 3 种要点判定组合、得分 0.551-0.9286、pass/fail 翻转；
温度 0 仍有 4 种组合——**波动来自服务端非确定性，幂等缓存才是正解**。

1. `src/llm/client.py`：`PURPOSE_TEMPERATURES` + `temperature_for()`，`quiz_grade` 温度降为 0
   （消除客户端采样噪声；`_call_api` 支持 temperature 覆盖）。
2. `grading_cache` 表（tables.sql + `migrate._ensure_grading_cache_table`）与
   `src/services/grading_cache.py`：缓存键 = SHA256(模型|prompt 版本|题目|参考答案|要点|作答)，
   命中即复用模型判定——重判逐字复现、零模型调用；坏数据当未命中；首写为准。
3. `answer_service._grade_answer`、`quiz_service.grade_with_llm` 接入缓存；
   缓存存模型语义意见，分数与达标仍由规则层实时算；记忆背景不进键（口径：不改判定）。
4. `scripts/eval_grading_consistency.py`：自一致性实验（温度 0.2 vs 0 对照）。

## 影响范围

- 仅判分链路（日常训练 + 测验）的调用行为；判分口径、达标规则、降级路径不变。
- 10 个既有测试桩签名补 `*args, **kwargs`（`_call_api` 增加 temperature 参数的连带）。
