# 20261115 fix 客观题题型分流接通主链 + 选项 UI + 固定卡片 + 完整计划视图

> 类型：fix（判分）+ feat（计划视图）｜用户报告的三个问题：选择题没有可选 UI、
> 卡片高度随题干变长、想看完整计划并提前做。排查后发现 UI 只是表层，
> 根因在判分与数据链路。

## 根因与修复

### 1. 判分无题型分流（真根因，最深的一处）

`answer_service._grade_answer` 从未按题型分流——**选择题也被送进 LLM 语义判分**
（payload 里没有 question_type/options），违反 ADR-0022 硬约束（客观题 MUST NOT
调模型），plan_item #139 的选择题被语义判出 partial 要点即实例。修复：

- `grading_service.grade_objective()`：choice/fill 确定性判分统一入口（qa 返回 None）；
  新增 `parse_options()` / `correct_key_of()`（options JSON 容错解析）；
- `answer_service._grade_answer` 按题型分流：choice/fill 走规则（零 LLM）、qa 走原链路；
- `quiz_service.grade_with_llm` 同样分流（客观题覆盖模型意见）；
- 判分来源落库：`practice_attempts.source` 枚举新增 `'rule'`（表重建迁移），
  `plan_items.graded_by` 记录真实来源（rule/llm）。

### 2. 题型与选项未随题固化（数据链路）

出题响应里的 question_type/options 从未落库，判分时丢失。修复：

- `plan_items` 新列 `question_type` / `options`（随题固化，与 points 同模式）；
  迁移 `_PLAN_ITEM_QUESTION_COLUMNS` 扩展 + 老库 ALTER 补列；
- `ensure_question` 出题时一并落库；选择题选项缺失/非法时降级 qa 语义判分（不伪造客观判定）；
- `plan_service.question_meta(plan_id)` 提供渲染数据。

### 3. API 与前端补齐

- `/api/today` 与 question 端点返回 `question_type` + `options`（**is_correct 不下发**，
  正确性判定留在后端）；新增 `GET /api/trainings/{id}/plan-items`（全部轮次视图）；
- TaskCard：choice 渲染单选列表（提交 key）、fill/qa 维持文本作答；
  未到期轮次显示「未到期 · 可提前练」；
- 卡片固定高度：`.task-body` max-height 540px、`.question-box` max-height 260px
  （长题干内部滚动，不再撑高卡片）；
- TrainingDetailView 新增「完整计划」页：全部轮次按到期日排序，未到期轮次可直接
  展开作答（提前练——动作端点本不设到期门，guard 只校验可见性）。

## 追加（同日第二轮，commit a761056）

用户验收反馈三连修：

1. **宽度跳变**（非高度）：section 切换时页面滚动条出现/消失导致水平位移——
   `html { scrollbar-gutter: stable }` 预留滚动条槽位。
2. **训练路径条目跳转后"找不到训练项"**：数据诊断（全部训练路径项与计划轮次
   完全匹配，无缺失）后确认是 UX 问题——自动展开的卡片在长列表深处无定位。
   修复：TaskCard `autoOpen` + `scrollIntoView`（滚动到卡片居中）；数据层加
   `POST /plan/regenerate` 补齐缺失轮次端点（generate_plan OR IGNORE 幂等）+
   前端「补齐缺失轮次」按钮（本轮数据诊断无缺失，按钮为路径重生成后的保险）。
3. **「已记录练习，未系统判分」死状态**（practice-only 或旧判分不可用遗留）：
   给出「重新作答并判分」按钮——choice 走规则判分补上判定；测试钉住
   "只练不判 → 重新作答 → 判分落库（source=rule）、attempt 恰一条"。

测试 **321 passed + 30 subtests**；服务已重启，新端点验证 401（鉴权要求而非 404）。

## 追加（第三轮，桌面优先固定布局）

用户截图取证：训练详情页在有效视口 <768px 时切到移动端降级布局（侧栏隐藏、
标签折行、内容列 ~390px 居中），恢复宽视口又切回桌面——「UI 大小不断变」的根源。
个人版为桌面优先工具：移除 ≤768px 断点（侧栏/topbar/tabbar 降级行为），`.shell`
最小宽度 1080px（过窄视口横向滚动而非变形）。配合 scrollbar-gutter: stable，
宽度恒定。移动端适配如未来需要（手机访问），应重新设计而非复用本断点。
