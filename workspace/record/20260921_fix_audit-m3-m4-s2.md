# 20260921 · fix · 审计 M3 / M4 与 S2 收口（回指清理、探测告知、影响面漏报）

## 变更摘要

按审计报告收掉三条与"数据可信"直接相关的结论：

1. **M3（刷新快照后回指悬空）**：`parse_source` 在**切片被整体替换**后自动调用 `path_service.validate_item_chunk_links`
   清理训练项的悬空出处；新增 `refresh_snapshot_report`，刷新后返回**影响面**（新增/删除/修改的小节）
   与**受影响的训练项数**，资料页会把这句提示展示给用户。
2. **M4（探测静默截断）**：新增 `edge_service.count_knowledge_points` 与 `ProbeResult.truncated`；
   新建向导第 3 步现在显示"资料里共 N 个知识点，本次只探测前 M 个，其余在路径里按资料顺序覆盖"。
3. **S2（影响面只比第一片）**：`compute_impact` 改为**把同一标题下的所有切片拼起来再比对**，
   长小节被切成多片时，后续片段的改动不会再被漏报。

## 关键实现细节

1. **清理只在实际替换时触发**：`parse_source` 先探测"该来源原本有没有切片"，只有替换过才去清理回指，
   避免每次导入都跑一遍全表扫描。
2. **共享连接不跨界**：调用方传了 `conn` 时，清理复用同一个连接（不在别人事务里另开连接）；
   自己开的连接则单独处理，失败只记日志，不影响解析/刷新结果。
3. **告知而不是自动补探**：探测上限暂不改（ADR-0018 的成本控制），但用户现在知道"整份资料有多少个知识点、
   这次探了几个"，并且可以用「重新定位理解边缘」再来一轮。
