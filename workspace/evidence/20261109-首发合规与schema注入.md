# 20261109 首发合规与 Schema 注入实验

> 触发：token 成本梳理中发现的真问题——四个新一代模板（train_question / quiz_grade /
> quiz_variant / explanation）要求里写"字段见 schema"，模板里却没有 `{schema}` 占位符，
> 模型从未见过输出格式定义，首发输出全靠盲猜。
> 工具：`scripts/eval_schema_first_pass.py`（本次新增）。环境：阿里云免费端点
> `deepseek-v4.1-flash`，quiz_grade 真实载荷（plan_item #235，3 条固化要点），
> 每臂单发 6 次、无重试。DB 只读。

## 结论

| 对照 | 首发合规 | tokens_in |
|---|---|---|
| 修复前 v1.2.0（不展示 schema） | **0/6** | 564 |
| 修复后 v1.3.0（prompt 内嵌 schema） | **6/6** | 873（+309） |

**+309 tokens 输入买断一整个重试往返**：旧行为每次判分实际跑两轮
（首发不合规 → 错误反馈重试），第二轮请求还要回显首次输出与反馈，
输入侧 564+~600、输出侧首发废稿照付、延迟约两倍；修复后单轮直达。
**净账是省的**（单次判分少一次 API 往返、少一份废稿输出），且判分平均延迟
从"秒级×2"回到"秒级×1"。

延迟参考（本实验单发实测）：修复前 2.6-14.5s（含长尾）；修复后 2.7-5.3s、无长尾。

## 修复内容

1. 四个模板补 `{schema}` 占位（老 11 个模板同款句式：
   "请按以下 JSON Schema 严格输出…"），版本：
   train_question v1.0.0→v1.1.0、quiz_grade v1.2.0→**v1.3.0**、
   quiz_variant v1.0.0→v1.1.0、explanation v1.1.0→v1.2.0。
2. `tests/test_prompt_schema_contract.py` 守卫：凡 SCHEMA_REGISTRY 注册了 schema 的
   用途，模板必须含 `{schema}` 占位（防回退）；四个修复模板的版本号一并钉死。
3. quiz_grade 版本升级自动使 `grading_cache` 旧键失效（键含 prompt 版本）——
   模型现在看得见 schema，重判一次是期望行为。

## 边界

- 实验臂为 quiz_grade 单用途、单载荷、n=6、单端点（免费额度 flash 档）；
  结论是"该档模型下占位符决定首发合规"的方向性证据，不是跨模型普适结论
  （更强模型可能盲猜也能对，但占位符没有下行风险）。
- `_schema_dump` 仍为 indent=2 的 pretty 序列化（~335 tok）；紧凑序列化可再省
  ~190 tok/次，但会同时改动全部 15 个用途的 prompt，留作单独优化，本次不动。
- 全量测试 **308 passed + 30 subtests**（2026-11-09）。
