# 判分一致性标注练习集（Redis 主题，10 条要点）

> 用途：让你先跑通一次人工标注，验证流程可行再扩大样本。
> 用法：**只填【你的判定】这一列**，先别看系统判定。填完再跑系统判分做对比。
> 判定取值：`hit`（答到且正确）/ `partial`（说到一部分）/ `wrong`（说反了）/ `missing`（完全没提）/ `unsure`（拿不准）

---

## 一、题目与要点

**Q1. 为什么 Redis 单线程模型不会出现锁竞争？**（要点 3 条）
**Q2. RDB 和 AOF 两种持久化方式的区别是什么？**（要点 3 条）
**Q3. Redis 6.0 之后在 IO 上做了什么变化？**（要点 2 条）

## 三、这套练习的"坑点"在哪

刻意安排了几种容易被判错的类型，你标完可以对照：

| 类型 | 行 | 为什么容易错 |
|---|---|---|
| 完全正确 | Q1-p1、Q2-p1 | 应该都是 `hit` |
| 换个说法但意思对 | Q1-p2、Q3-p2 | 表述不同不影响判定，也是 `hit` |
| 完全没提 | Q1-p3 | 应为 `missing`——注意"没说"不等于"说错" |
| **说反了/说错了** | Q2-p3 | 作答提到 AOF 但把机制说成了锁 → `wrong`，比 missing 更糟 |
| 沾边不完整 | 最后一行 | "都是持久化方式"没说区别 → `partial` |

## 四、填完之后怎么用

1. 把你的判定抄进 `判分一致性标注-工作表.csv` 的 `human_verdict` 列；
2. 让系统对**同一批作答**跑一遍判分，填 `system_verdict`；
3. 算两个数：
   - **逐条一致率** = 相同条数 ÷ 总条数（`unsure` 剔除）
   - **结论一致率** = 每题按规则算出的 pass/fail 与系统一致的题数 ÷ 题数
4. 数字写进一份证据报告，并在 change 的 tasks 8.1 打勾。
