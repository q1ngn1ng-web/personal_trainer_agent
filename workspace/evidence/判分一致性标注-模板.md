# 判分一致性人工标注：模板与规则

> 目的：验证"系统判分"与"人工判断"是否一致，产出 change `learner-memory-and-grading` 中
> tasks 8.1（判分一致性）与 8.2（重复判分稳定性）所需的证据。
> 状态：**待执行**。完成前不得在任何对外材料中声称这两项数据。

---

## 一、要标注什么

标注的**不是**"这道题答得对不对"，而是**逐条要点是否被答到**——这正是模型在判分链路里
唯一被允许做的判断。结论（通过 / 不通过）由规则算，所以只要要点判定对齐了，结论自然对齐。

| 判定 | 含义 | 例子（要点：Redis 单线程避免锁竞争） |
|---|---|---|
| `hit` | 说到了，且正确 | "单线程执行命令，所以不存在多线程抢锁" |
| `partial` | 说到了一部分，不完整或不精确 | "单线程效率高"（沾边但没说锁） |
| `wrong` | 提到了但说反了 / 说错 | "用锁保证线程安全" |
| `missing` | 完全没涉及 | 只答了持久化相关的内容 |
| `unsure` | 你自己也拿不准 | 单独统计，**不并入一致率** |

## 二、标注规则（保证结果可信）

1. **盲标**：先只看"题目 + 要点 + 用户作答"，**不要先看系统给的判定**，否则会被带偏。
2. **同一把尺子**：四态定义与 prompt 里给模型的一致（见上面表格）。
3. **只判要点，不判总分**：不要替系统算分数、判是否通过。
4. **拿不准就标 `unsure`**：不要硬猜。`unsure` 单独统计，从一致率里剔除。
5. **建议隔天复标一遍**：同一个人隔一天再标一次，比较两次自己的一致性（intra-rater）。
   个人项目单人标注 + 复标，是学界可接受的做法；有条件找第二个人交叉标注更好。

## 三、标注对象与规模

- **题目数量**：20—30 题（对应 tasks 8.1 的要求）；
- **要点条数**：主观题至少 3 条要点，所以总判定条数大约 60—100 条；
- **抽样方式**：从已作答且有 `question_points` 的题里**随机抽**，不要专挑答得差的；
- **样本量声明**：完成后的结论必须标注"样本量有限，结论不外推"。

## 四、工作表现成什么

用同目录下的 `判分一致性标注-工作表.csv`，列的含义：

| 列 | 谁填 | 说明 |
|---|---|---|
| `question_id` | 导出 | 题目标识 |
| `question_type` | 导出 | choice / fill / qa |
| `question` | 导出 | 题干 |
| `point_id` / `point_text` | 导出 | 要点清单（随题固化） |
| `weight` / `is_required` | 导出 | 权重与是否必答 |
| `user_answer` | 导出 | 用户作答 |
| `human_verdict` | **你填** | hit / partial / wrong / missing / unsure |
| `human_note` | **你填** | 一句话理由（可选，但建议写） |
| `system_verdict` | 导出 | 系统判定（**看之前先填完 human_verdict**） |
| `system_repeat_verdict` | 导出 | 同一份作答**再跑一次**系统的判定，用于稳定性 |

## 五、算出来的三个数（这就是证据）

```
1) 逐条一致率 = 人工与系统判定相同的条数 ÷ 总条数（剔除 unsure）
2) 结论一致率 = 人工按规则算出的 pass/fail 与系统 pass/fail 相同的题数 ÷ 总题数
3) 稳定性   = 同一份作答跑两次，判定相同的条数 ÷ 总条数
```

进阶（可选）：用 Cohen's kappa 替代简单一致率——因为"四态随机猜"也能蒙对一部分。
`sklearn.metrics.cohen_kappa_score` 一行就能算，把两组判定传进去即可。

**口径要求**：三个数都要写清分母、样本量、是否剔除 `unsure`，否则数字不可比。

## 六、执行步骤（照着做就行）

1. 从数据库导出工作表：抽 20—30 道有要点清单的题，连同用户作答与系统判定；
2. **先只填 `human_verdict`**（把 `system_verdict` 那列先遮住）；
3. 填完再展开 `system_verdict`，算逐条一致率与结论一致率；
4. 同一份作答再跑一次系统判分，填 `system_repeat_verdict`，算稳定性；
5. 把三个数写进 `workspace/evidence/`（新建一份报告），并在 change 的 tasks 8.1 / 8.2 打勾。

## 七、常见坑

- **别用系统判定反推人工判定**：那叫自证，不叫验证；
- **别只挑错的题标**：样本要有答得好的题，否则一致率虚高或虚低；
- **别把 `unsure` 塞进分母**：说不清的条目不参与一致性计算；
- **别把结论建立在 20 题的百分比上**：样本量小，只能说"初步一致"，不能说"准确率 X%"。
