# 效果证据（Evidence）

这里放"做完到底有没有用"的可核验材料。**没有证据的结论不进简历、不进面试口述、不进对外文档。**

## 三条硬规则

1. 每个数字写清 **口径 / 样本量 / 时间窗口**——"完成率 80%"不合格；"7 天内到期任务完成数 ÷ 到期任务总数，样本 42 条，2026-09-15 ~ 09-21"合格。
2. 每个结论必须指向产生它的脚本或原始报告（相对路径）。
3. 没测过的一律标 `【待验证】`，禁止估算百分比、用户量、QPS、准确率、节省工时。

## 命名

`YYYYMMDD-主题.md`，例如 `20260920-计划生成耗时.md`。原始报告放 `workspace/evidence/raw/`。

## 记录模板

```markdown
# 20260920 计划生成耗时

## 结论
【待验证】端到端计划生成 P95 = ? 秒（当前只有一次手动观察，不足以下结论）

## 指标明细

| 指标 | 口径 | 样本 | 时间窗口 | 结果 | 脚本 |
|---|---|---|---|---|---|
| 计划生成耗时 P50 | 从提交目标到计划确认的毫秒数 | 20 次 | 2026-09-20 | 【待验证】 | scripts/... |

## 方法
怎么测的、参数怎么设的、环境是什么（机器配置 / 模型 / 是否冷启动）。

## 已知局限
样本量、环境差异、是否可复现、哪些结论不能外推。
```

## 建议优先补的三类证据

| 优先级 | 指标 | 为什么 |
|---|---|---|
| P0 | 评测可信度（人工标注集的准确率 / 一致率） | 评测不可信，调度就会放大错误；这也是"和 ChatGPT 生成计划有什么区别"的答案 |
| P0 | LLM 结构化输出通过率、失败降级率 | 直接反映 Harness 是否可靠，`llm_calls` 表就能算 |
| P1 | 端到端耗时、单次评测 token 成本 | 成本与体验的硬指标，面试常问 |
