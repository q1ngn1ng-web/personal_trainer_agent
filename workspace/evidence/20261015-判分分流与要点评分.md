# 20261015 判分分流与要点评分（证据）

> 关联 OpenSpec change：`learner-memory-and-grading`（tasks 1.1—1.4、2.1—2.4）
> 关联 ADR：ADR-0022

## 一、口径

| 项 | 口径 |
|---|---|
| 覆盖率 | Σ(命中权重 + 0.5 × 部分命中权重) ÷ Σ总权重 |
| 正确性 | 1 − 错误要点权重 ÷ 作答涉及的要点权重（未作答不参与） |
| 得分 | 覆盖率 × 正确性（0—1） |
| 必答否决 | 必答要点未命中 → 该题不通过 |
| 分流规则 | choice / fill 确定性判分；qa 要点评分 |

## 三、关键断言

1. **客观题不调用大模型**：`test_objective_grading_does_not_call_llm` 用 monkeypatch 把
   `src.llm.client.complete` 替换为抛异常的桩，选择题与填空题判分仍正常通过——证明这两条路径没有触碰模型。
   判分结果中的 `graded_by` 字段固定为 `rule`，可作为后续接入时的断言点。
2. **答满但说反 < 只答对两条**：`test_wrong_answer_worse_than_missing` 断言前者的 `score` 严格更小。
3. **三点答两点 = 2/3**：`test_coverage_two_of_three`（等权情形下 `coverage == 2/3`）。
4. **必答缺失一票否决**：`test_required_missing_vetoes_pass`，且 `required_missing` 可定位到具体要点。
5. **迁移可重复执行**：`test_migrate_adds_grading_columns_to_old_db` 在模拟老库上补列并建表，
   第二次调用返回空列表。

## 四、未覆盖 / 待验证

- 达标阈值已定为 `0.8`（2026-10-15 决策），但**未经人工标注样本校准**【待验证】；
- 整场评分权重已定为客观题 `0.4` / 主观题 `0.6`；`overall_score` 已实现并有用例，
  但**尚未接入测验链路**（阶段 5）；
- 判定规则（阈值 + 必答否决）尚未接入 `core/mastery.evaluate` 与 `attempt_service`；
  **接线依赖阶段 3**（题目先带要点清单、判分 prompt 产出逐条判定）；
- 测验链路（`quiz_service`）尚未调用新的判分入口（tasks 2.4 的接线部分）。

## 五、阶段 3（出题）的验证口径

- **要点随题固化**：`save_question_points` 落库后由 `load_points` 读回，并直接驱动 `grade_question`
  算出覆盖率与缺失要点（用例 `test_points_round_trip_and_drive_grading`）。
- **干扰项可溯源**：`validate_generated_question` 在传入资料原文时，会把"原文中找不到依据"的选项
  判为疑似编造并拒绝落库（用例 `test_choice_distractor_must_be_grounded_in_source`）。
- **校验不通过不落库**：`save_generated_question` 在校验失败时直接返回问题列表，不留半条数据。

## 六、阶段 4（记忆）的验证口径

```bash
uv run pytest -q tests/test_memory_service.py
# → 9 passed
```

- **错因推导零模型调用**：`derive_mistake_reasons` 是纯函数，由要点四态推出错因枚举
  （missing→记忆缺失 / wrong→概念混淆 / partial→表达不完整 / 必答缺失→关键遗漏）。
- **画像与错因可聚合**：`knowledge_profile` 用一条 SQL 聚合知识点 × 题型的作答数与均分，
  并标出薄弱项；`mistake_reason_counts` 能把"同一错因出现几次"算出来。
- **上下文规模可量化**：`render_context` 返回渲染后的 token 估算与"把原始作答全塞进去"的
  对照值，两者之比即压缩比（用例断言 `< 1`）。
- **开关默认关闭**：`is_mistake_analysis_enabled` 默认 False；分析文本存 `mistake_analysis` 表，
  不覆盖 `practice_attempts.mistake_reasons`（有用例断言）。

> 估算口径：中文按字、拉丁按 4 字符 1 token，仅用于相对规模对比，不是计费口径。

## 七、阶段 5—7 的验证口径

```bash
uv run pytest -q
# → 253 passed, 1 skipped, 30 subtests passed in 183.94s（基线 216 passed）
```

- **整场加权评分（5.1）**：`pair_weighted_score` 按题型权重聚合；用例断言
  "客观满分 + 主观零分 = 0.4"（客观 0.4 / 主观 0.6）；全为 None 时返回 None，不伪造分数。
  `finish_assessment` 改为优先使用加权分，历史题无分数时退回通过比例。
- **按需解析（6.1 / 6.2）**：用例断言解析会读取题目关联的资料片段原文
  （`source_text` 内含切片正文），并把解析文本落 `explanations` 表；题目不存在时返回 `ok=False`。
- **自适应配比（7.1）**：用例构造"选择题很弱、问答题很强"，断言配比只对弱题型加压
  （choice=1.0，qa 不出现）；无数据时返回空字典。
