# 工作流引导提示词（可复制到任意项目）

**用法**：在一个新项目的第一轮对话里，把下面「提示词正文」整段粘贴给 Codex（或任何 AI 编程工具）。
它会先侦察仓库、再问你三个问题，然后把四件套落成文件，不写业务代码。

**为什么这样写**：不是让 AI"生成一堆文档"，而是让它**先问你问题、再落盘**，并且把"不许编数据"写成硬规则。

---

## 提示词正文（从这里开始复制）

我要在这个项目里建立一套「文档跟着代码走」的工作流。请先不要写业务代码，先只做搭建。

目标：让下面四类信息都有固定载体，并且随代码同步更新——

1. 决策（为什么选 A 不选 B）→ MADR 格式的 ADR
2. 规格与验收（要做什么、怎么算做到）→ OpenSpec（若项目已用；否则用 `specs/` 目录）
3. 证据（做完到底有没有效果）→ 评测脚本 + 证据记录
4. 规则（AI 每次开工读什么、必须产出什么）→ AGENTS.md

请按顺序执行：

**第一步：侦察（只读，不改任何文件）**

- 读现有的 AGENTS.md / README / docs / OpenSpec 配置（若有），总结当前的技术栈、目录约定和已存在的文档规范
- 列出仓库里已经有的事实：已实现的能力、已记录的缺陷、已有的测试
- 明确指出：哪些结论目前没有证据支撑，哪些文档是过期或空模板

**第二步：问我三个问题（一次问完，等我回答后再继续）**

1. 这个项目解决谁的什么问题，怎么算成功？
2. 有哪些硬约束（部署环境、成本、数据合规、时间、团队约定）？
3. 已经做过的关键选型或踩过的坑有哪些？

**第三步：落地文件**

- 更新 AGENTS.md，加入四节：「文档与决策工作流」「开工前读取分级（必读 / 按任务触发 / 不要整体加载）」「硬性门禁」「收尾检查清单」
- 建 `workspace/decisions/`：`ADR-0000-template.md`（一页模板：状态 / 背景 / 备选方案表 / 决策 / 后果与验证）+ 索引 README
- 若项目用 OpenSpec：在 store 的 `config.yaml` 补 `context`（技术栈、分层、核心设计原则）和 `rules`（proposal 必须含 Non-goals 与备选方案；tasks 必须含验收命令）
- 建 `workspace/evidence/`：写清证据规则（口径 / 样本 / 时间窗口 / 脚本路径）和记录模板
- 把第二步的回答整理成第一批 ADR，每条一页，缺证据的地方标 `【待验证】`

**第四步：给我三样东西**

- 一份改动清单（文件路径 + 一句话说明）
- 一条"以后每次任务"的固定口令
- 你认为当前最缺的一条证据，以及拿到它的最小动作

**约束**

- 不要写业务代码
- 不要编造数据、客户、指标、用户量、性能数字
- 每份文档一页以内，能一眼看完
- 所有改动走 git，可回滚

## 这个提示词里藏着的四个设计

| 设计 | 为什么 |
|---|---|
| 先侦察再动手 | 避免 AI 凭空生成一套和仓库现状不符的模板 |
| 先问三个问题 | 背景、约束、选型只有你知道，AI 问出来的才真实 |
| 「缺证据标待验证」 | 防止 AI 用看起来很专业的假数字把文档填满 |
| 要求指出"哪些是空模板" | 顺手就能发现 `Purpose: TBD` 这类归档没走完的问题 |

## 如果项目已经在跑

把第一步换成：

> 先审计现状：列出所有现有文档，标出"过期 / 空模板 / 与代码不符"三类，再按第三步补齐缺的层。

这样它不会重复造你已经有的东西。
