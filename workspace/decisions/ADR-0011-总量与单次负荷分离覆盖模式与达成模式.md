# ADR-0011 总题量与单次负荷分离，覆盖模式与达成模式并存

- **状态**：已采纳
- **日期**：2026-09-20
- **关联**：训练路径生成环节（proposal 待立项）

## 背景

训练过程中用户的节奏会波动：某几天状态差、答题超时。此时系统该怎么调？

直接把题量减少会破坏"必须掌握全部内容"这类目标的完整性——企业培训、考证场景下，**少练一个知识点就是没覆盖**，不是"进度慢一点"那么轻。

另一方面，用户自定目标时（"能写出来就行"），提前达标就该收工，没必要把清单刷完。

这两种诉求不能用一个模式表达。

## 备选方案

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 单一模式，总量随表现浮动 | 实现最简单 | 覆盖型目标会漏内容，培训场景直接失效 | 否 |
| 总量与单次负荷绑定 | 实现简单，符合直觉 | 用户疲劳时只能硬扛或直接放弃当天 | 否 |
| **总量与单次负荷分离 + 两种模式** | 既保证覆盖完整性，又照顾实际节奏 | 需要让用户选择模式；覆盖模式下时间预算必须弹性 | **采纳** |

## 决策

1. **覆盖模式**（企业培训、考证等"必须掌握全部指定内容"的目标）：
   - 总题量**锁定**，必须覆盖全部知识点
   - 单次负荷**可调**，状态差就少做几项、剩余顺延
   - 难度**可降**，但**不得因难度高而跳过任何知识点**
2. **达成模式**（用户自定验收标准）：达标即可提前结束，总量可调。
3. **超时处理规则**：连续 3 项实际耗时超出预估 → 只降低单次负荷，**不降标准、不减总量**。
   原因是超时说明"一次吃不消"，而不是"学不会"，两者的处理方式不同。
4. **时间预算的弹性由用户选择**：覆盖模式下顺延今天欠的项，要么延长截止日，要么压缩后续休息日，由用户决定，系统不擅自安排。
5. 上述调整**全部由规则依据数值触发**，不由 LLM 判断。

## 后果与验证

- **代价**：需要引入模式选择，并在界面与数据模型上区分两种目标的调整策略
- **代价**：覆盖模式可能延长总周期，需要向用户交代清楚
- **验证方式**：手动场景——模拟连续 3 项超时，观察单次题量下降而**总题量与覆盖范围不变**；**【待实测】**
- **重评估触发条件**：若用户几乎从不主动选择覆盖模式，考虑将其改为默认隐藏的高级选项；反之若覆盖模式使用频繁，可考虑支持"部分覆盖"（指定只覆盖某几章）
