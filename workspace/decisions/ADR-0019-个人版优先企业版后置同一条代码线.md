# ADR-0019 个人版优先，企业版后置，同一条代码线

- **状态**：已采纳
- **日期**：2026-09-20
- **关联**：`org-and-roles` 与 `training-assignment` 后置；ADR-0012 / ADR-0013 的预留字段继续有效
- **修订**：原表述"企业版是个人版的超集"不准确——两者功能集有交集但不相等；差异的承载方式见 ADR-0020

## 背景

企业化设计（组织、角色、培训任务、企业指标）规格已经写完，但"该不该现在实现"是另一个问题。

个人版的最小闭环是**意图驱动的自适应训练 AI 教练**；企业版是它的放大器。三条现实约束决定了顺序：

1. **个人版能立刻产生真实自用数据**；企业版没有真实企业环境，只能产出构造数据
2. 一个人的时间预算有限，先做权限与报表会把"验证内核是否有效"无限推迟
3. "我每天在用，这是真实数据" 比 "我做了多租户" 更有说服力

## 备选方案

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 先做企业版（含权限、组织、报表） | 叙事完整 | 没有企业环境，数据只能构造；内核验证被推迟 | 否 |
| 先做个人版，企业版另开 git 分支 | 两版互不干扰 | 分支是代码隔离，不是产品隔离；企业版是超集，分叉后必然重复维护并废弃一支 | 否 |
| **先做个人版，企业版后置，同一条代码线** | 内核先验证；企业版靠预留字段与分层扩展接上 | 需要一开始守住数据隔离与分层约定 | **采纳** |

## 决策

1. **不做 git 分支**。企业版是个人版的超集，走同一条代码线，用可选的组织维度区分。
   **个人版 = 只有一个用户的组织**：`org_id` 填默认值、`scope=personal`、角色只有 owner。
2. **个人版定位**：意图驱动的自适应训练 AI 教练（单用户自用）。
3. **企业版相关 change 后置**：`org-and-roles` 与 `training-assignment` 保持提案状态，**不 apply、不 archive**。
4. **保留组织维度字段**：`org_id` 与 `scope` 继续按 ADR-0012 / ADR-0013 预留，个人版填入默认值，**不实现任何鉴权**。
   理由：字段的代价近乎为零，而数据隔离是事后最难补的一类改动。
5. **个人版必须保留企业指标所需的原始数据**：开始日期、首次达标日期、必修完成情况。
   即使个人版不展示"首次达标周期""必修覆盖率"，这些时间点也必须记录，否则将来算不出来。
6. **面试材料分两层表述**：个人版说"已实现"，企业版说"已设计、已做前瞻性预留"，不得混说。

## 后果与验证

- **代价**：个人版实现时仍需维护 `org_id` 的默认填充（一行逻辑）
- **代价**：企业版的功能在个人版中不可见，演示时只能靠设计与 ADR 说明
- **收益**：内核先跑起来并产生真实数据；企业版将来不需要回改数据模型
- **验证方式**：个人版跑通「描述 → 澄清 → 选来源 → 定位边缘 → 生成路径 → 训练 → 达标」完整闭环，并积累真实使用记录——**【待实测】**
- **重评估触发条件**：若接触到真实企业用户或需求，立即启用 `org-and-roles`；若长期无企业场景，考虑删除预留字段以简化
