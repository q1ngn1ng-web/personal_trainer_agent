# ADR-0012 文档格式支持范围与 OCR 策略

- **状态**：已采纳
- **日期**：2026-09-20
- **关联**：OpenSpec change `training-source-selection`

## 背景

`training-source-selection` 初稿的非目标里写着"不做扫描件 OCR、不做 Word / Excel"。

复核后认为这个排除过宽。企业培训场景里的主流形态并不是 PDF：

- **Word（.docx）**：讲义、制度文件最常见的交付格式
- **Excel（.xlsx）**：培训题库的常见形态，列通常是题干 / 选项 / 正确答案 / 解析
- **扫描件**：老制度文件、纸质考核材料，确实存在但不是主流

原来排除的理由是"每多一种格式就多一类失败模式"。这个理由成立，但它推出的是**分批支持 + 独立验收 + 失败显式化**，而不是一律不做。

## 备选方案

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 只支持 PDF / Markdown / txt | 链路最短，失败面最小 | 企业场景的主流形态进不来，产品直接不可用 | 否 |
| 一次支持全部格式含 OCR | 覆盖最全 | 同时引入版式与 OCR 两类不可控因素，出错时无法归因 | 否 |
| **分批：先加 Word 与 Excel，OCR 延后并强制人工确认** | 覆盖主流形态，失败可归因 | 需维护多条解析分支与各自的验收标准 | **采纳** |

## 决策

1. **第一批格式**：PDF、Markdown、txt（已有）+ **Word（.docx）** + **Excel（.xlsx）**
2. **Excel 特殊处理**：识别表头语义（题干 / 选项 / 正确答案 / 解析），**直接解析为结构化题目**，而不是当普通表格按文本切片——题库的价值就在结构化
3. **OCR 列入第二批**，触发条件为：真实用户资料中扫描件占比超过 20%，或出现明确的扫描件培训材料
4. **OCR 的三条硬要求**：
   - 保留原图，供人工核对
   - 结果标记 `ocr=true` 与置信度
   - 低置信度切片在界面上提示"需人工确认"，**不得默认当作可用来源**
5. **每种格式有独立的解析验收标准**（每格式至少 2 份真实样本）；失败一律 `parse_status=failed` 并记录原因

## 后果与验证

- **代价**：解析分支变多，测试矩阵变大
- **代价**：OCR 引入后质量不可控，必须保留"人工确认"环节，否则会产出看似可用、实则错误的训练项
- **验证方式**：每种格式用 2 份真实文件跑通，统计解析成功率与切片质量——**【待实测】**
- **重评估触发条件**：若某格式的真实使用率低于 5%，考虑下线以降低维护面
