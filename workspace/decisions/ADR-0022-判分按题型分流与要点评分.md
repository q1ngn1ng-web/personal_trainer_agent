# ADR-0022 判分按题型分流，主观题按「要点覆盖率 × 正确性」给分

- **状态**：已采纳
- **日期**：2026-10-15
- **关联**：OpenSpec change `learner-memory-and-grading`（tasks 1.1—1.4、2.1—2.4）

## 背景

评测链路此前只有二元结论：`assessment_items.verdict` 是 `pass` / `fail`，
`reference_answer` 是一段自由文本，判分完全交给模型自由发挥。由此产生三个问题：

1. **判分不稳定**：同一份作答重复判分可能得到不同结论（要点由模型每次现抽）；
2. **不可解释**：用户只知道"错了"，不知道"缺哪条、哪条说反了"；
3. **客观题也在白花钱**：选择题、填空题本身有确定答案，却统一走了大模型判分——付出 token 与延迟，还把 100% 的确定性换成了随机性。

同时新场景要求支持选择题、填空题，判分必须按题型区分。

## 备选方案

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 继续全部交给模型自由判分 | 实现最简单 | 不稳定、不可解释、客观题白付成本 | 否 |
| 只算要点个数（3 个答 2 个 = 66.7%） | 直观、好实现 | 只测覆盖率不测正确性，"答满但说反一条"仍得满分；掩盖"漏掉的正是命门" | 否 |
| **按题型分流 + 覆盖率 × 正确性 + 必答否决** | 客观题零成本零延迟；主观题可解释、可校准 | 要点清单需要随题固化，增加一次生成与维护成本 | **采纳** |

## 决策

- **题型分流**：`choice` / `fill` 走确定性判分，**不调用任何大模型**；`qa` 走要点评分。
- **要点四态**：命中 / 部分命中 / 错误 / 缺失。覆盖率 = Σ(权重 × 系数) ÷ Σ权重；
  正确性 = 1 − 错误权重 ÷ 作答涉及权重（"说反了"比"没说"更糟）；得分 = 二者之积。
- **必答否决**：标记为必答的要点未被命中时，该题直接不通过，不被其他要点的高权重拉回。
- **要点随题固化**：存于 `question_points`，判分时只读不生成——与评测集用 `gold_anchors` 是同一个道理。
- **填空题本期不处理同义答案**：归一化后精确比对，语义等价留待后续。

## 后果与验证

- **代价**：每道主观题要多维护一份要点清单；权重与阈值目前是启发式初值。
- **验证方式**：`tests/test_grading_service.py` 覆盖覆盖率、正确性、必答否决、题型分流与迁移；
  其中一条用 monkeypatch 把 LLM 客户端换成抛异常，断言客观题判分仍能通过，以此证明它没走模型。
- **【待验证】**：达标阈值 `DEFAULT_PASS_THRESHOLD = 0.6` 是启发式取值，需要用人工标注样本校准后才能定稿。
- **未完成**：判定规则尚未接入 `core/mastery.evaluate` 与 `attempt_service` 的通过/连续管线（tasks 2.5）。
