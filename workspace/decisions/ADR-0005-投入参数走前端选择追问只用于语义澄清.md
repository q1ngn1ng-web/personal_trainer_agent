# ADR-0005 投入参数走前端选择，追问只用于语义澄清

- **状态**：已被 ADR-0006 取代
- **日期**：2026-09-19
- **关联**：修订 ADR-0004 的字段来源分配；OpenSpec change `goal-clarification-confirm`

## 背景

ADR-0004 把五个目标字段统一规定为"缺失就追问"。进一步推演后发现两个问题：

1. **周期、每周次数、每次时长是用户的投入承诺，不是知识问题。** 它们有确定的取值空间，
   用单选控件 3 秒就能选完，让 AI 一轮轮问出来属于把设计问题推给用户。
2. **每一轮追问都是一次流失机会。** 用户打开产品是想开始练，不是来填问卷。

真正只有用户自己知道、AI 猜不出来的，其实只有两件事：**练到什么程度**（目标等级）和
**怎么算学会**（验收标准）。

### 同类产品的常见做法

| 产品 | 用户要给的 | 系统决定的 |
|---|---|---|
| Duolingo | 每天多少时间 | 课程推进节奏 |
| Babbel / Memrise | 每周学几次 | 内容顺序 |
| 百词斩 / 墨墨 | 词书 + 每天背多少词 | 反推预计完成天数 |
| 备考类 App | 考试日期 | 反推每日任务量 |
| Coursera / edX | 选课程（课程自带周数） | 无 |
| Anki | 每天新卡 / 复习上限 | 复习间隔 |
| 松鼠AI | 先做诊断 | 知识图谱路径 |

规律：**要么用户给"每日投入"，系统反推总周期；要么用户给"截止日期"，系统反推每日量。**
几乎没有产品让用户同时猜两个，也没有产品让 AI 自由决定周期。

> 上表为产品常识整理，**未经实测，标【待验证】**；要作为对外证据前需亲手试用 2-3 款并留存截图。

## 备选方案

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 五个字段全部追问 | 流程统一，实现简单 | 追问轮次多、流失高；把可选项变成问题 | 否 |
| 五个字段全部做 UI 控件 | 用户负担最小 | `level` 与 `acceptance` 是语义判断，硬做成选项会失真 | 否 |
| **投入参数走 UI，语义字段走追问** | 用户负担最小，AI 只处理真正需要理解的部分 | UI 要多三个控件；两处输入需要合并逻辑 | **采纳** |

## 决策

1. **前端收集**：`horizon`（周期）、`weekly_frequency`（每周训练次数）、`daily_budget`（每次时长）。
   均有默认值，用户可直接跳过。
2. **追问收集**：`level`（目标等级）、`acceptance`（验收标准），这两项 AI 不得凭空猜定。
3. **追问双限**：软限 2 轮——到达后给出建议值并提示"可以直接用系统建议，也可以自己改"；
   硬限 3 轮——到达后强制收口，输出带 `inferred` 标注的草案。
4. **参数优先级铁律**：前端显式选择 > 追问得到 > AI 推断。**AI MUST NOT 覆盖用户显式给定的值**，
   推断出的值在 `goal_json.field_sources` 里标 `inferred`。
5. **AI 的职责是生成训练计划**：把「周期 × 每周次数」拆成阶段与训练项，而不是决定这些参数本身。

## 后果与验证

- **代价**：UI 多三个控件；`goal_json` 需记录字段来源；两处输入需要合并与冲突处理逻辑
- **代价**：软限后给默认值，可能让部分用户直接采用并不合适的默认值
- **验证方式**：
  - 单测断言"UI 给定的值不会被 LLM 输出覆盖"
  - 手动场景：不填任何参数直接开始，追问 ≤ 2 轮内完成澄清
  - 指标：澄清完成率、平均追问轮次、默认值采用率、事后修改率——**【待验证】**
- **重评估触发条件**：若实测默认值采用率 > 80% 且事后修改率 > 30%，说明默认值不合理，
  应改为强制用户显式选择，并新写 ADR 取代本条
