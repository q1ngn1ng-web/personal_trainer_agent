# ADR-0008 网络来源必须保存正文快照

- **状态**：已采纳
- **日期**：2026-09-20
- **关联**：OpenSpec change `training-source-selection`

## 背景

参照 Microsoft AI Learning Advisor 的做法，用户可以在来源页粘贴网址，把网页作为知识来源添加进去。

网页与上传文件的关键差别是**它会变**。如果只保存网址、需要时再实时抓取，那么训练项的出处将来
打开的可能已经是另一段内容——"每个训练项都能回指原文"这个承诺当场失效，而且无法复现当初的训练依据。

## 备选方案

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 只存网址，按需实时抓取 | 实现最简单，内容永远最新 | 出处不稳定、无法复现、离线不可用、每次打开都要联网 | 否 |
| 只存网址 + 打开时缓存 | 折中，少一次请求 | 缓存失效后仍指向新内容，只是把问题延后 | 否 |
| **抓取时保存正文快照 + 网址 + 时间戳** | 出处稳定、可离线核对、可对比变更 | 存储增加；快照会过期，需要用户手动刷新 | **采纳** |
| 定时自动重抓所有来源 | 永远最新 | 变成爬虫：请求量不可控、越界抓取、合规风险 | 否 |

## 决策

1. 抓取时保存 `snapshot_text`、`origin_url`、`fetched_at` 与 `checksum`
2. 界面同时展示**可点击的原始网址**与**快照时间**，用户清楚自己读的是哪一版
3. **不做定时自动重抓**；页面变更由用户手动点「刷新快照」，之后走增量重建与影响面流程
4. **只抓用户显式给出的网址**，不跟随页面内链接、不做站内爬取
5. 失败显式化：DNS 失败 / 超时 / 403 / 人机校验 / 正文为空（单页应用）一律记为
   `parse_status=failed` 并给出原因，绝不产出一个空的"可用来源"

## 后果与验证

- **代价**：存储量增加；快照会过期，需要用户参与刷新
- **代价**：JS 渲染的单页应用无法支持
- **验证方式**：
  - 手动场景：粘贴一个网址，能看到快照、抓取时间与可点击链接
  - 失败场景：用本次调研中真实遇到的三类失败各测一次——单页应用（`docs.dify.ai` 抓不到正文）、
    人机校验（`help.quizlet.com`）、连接超时（`support.google.com`）
  - **上述失败场景已由本次调研实际复现，可直接作为测试样本**
- **重评估触发条件**：若用户频繁要求"保持最新"，再评估加入定时重抓；但必须先解决
  抓取频率控制与 robots 约定，并新写 ADR 取代本条
