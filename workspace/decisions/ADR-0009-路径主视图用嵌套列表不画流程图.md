# ADR-0009 训练路径主视图用嵌套列表，不画流程图

- **状态**：已采纳
- **日期**：2026-09-20
- **关联**：训练路径生成环节（proposal 待立项）

## 背景

训练路径生成后需要一个展示形态。最初的考虑是画 mermaid 流程图，理由是"让学习者对即将呈现的内容有更好把握，同时迫使 AI 做全面推理"。

但这两个理由来自**学习新内容**的场景：学习者面对陌生领域时，需要先看到知识地图。而本项目是**训练**场景——学习者的结构认知来自培训文档本身的章节树，他打开系统的目的是"今天练什么、还剩多少"，不是先看一张知识地图。

此外还有一个实现层的风险：如果让模型直接输出 mermaid 代码，模型并不知道真实进度，**画出来的图会好看但与状态对不上**。

## 备选方案

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| mermaid 流程图（模型直接输出） | 开发最快，能展示结构 | 模型不知道真实进度，图与状态脱节；需要约束模型输出合法语法 | 否 |
| 纯列表 | 实现最简单 | 看不出阶段进度，用户没有掌控感 | 否 |
| **嵌套列表 + 进度条** | 结构与进度都清楚；进度来自数据库，永远真实；实现简单 | 出现真实分支或依赖时表达力不足 | **采纳** |
| 列表 + mermaid 双视图 | 兼顾 | 第一版是线性阶段，图的边际收益低，却要多写一套渲染 | 暂不 |

## 决策

1. 路径主视图使用**嵌套列表（阶段 → 训练项）+ 进度条**，第一版**不画流程图**。
2. 路径在数据库中**仍然是结构化数据**；列表只是它的一种渲染方式。
3. 将来若出现多支线路径或真实依赖，**新增一个渲染函数出图即可，不改数据模型**。
4. **不让模型直接输出 mermaid**——图必须由结构与真实状态渲染得出。

## 后果与验证

- **代价**：分支结构的表达力弱；将来若真要画图，需要额外实现渲染函数
- **代价**：失去了"迫使模型全面推理"的副作用（但路径生成用的是结构化 Schema 约束，本就有约束，不依赖画图）
- **验证方式**：路径页能看到阶段名、训练项清单、数量与题型分布、完成进度；截图存 `workspace/evidence/`——**【待实测】**
- **重评估触发条件**：出现多支线路径，或用户反馈"看不懂阶段的先后关系"，再引入图形视图
