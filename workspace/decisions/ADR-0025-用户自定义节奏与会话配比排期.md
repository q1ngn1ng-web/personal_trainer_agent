# ADR-0025 用户自定义节奏（总时长 × 次数）与会话配比排期，取代 ADR-0021 固定五轮

- **状态**：已采纳
- **日期**：2026-11-22
- **关联**：OpenSpec change `user-defined-training-plan`；**取代 ADR-0021**（其固定五轮模型降级为 `schedule_mode='legacy_v21'` 存量口径，零迁移）；配套 change `coach-memory-three-layers`（连败/偏好为控制器输入）

## 背景

ADR-0021 的固定五轮（+1/+3/+7/+15/30 天，每轮全量覆盖）上线后暴露三个偏差：

1. **投入参数无家可归**：总时长、训练次数既不问也不个性化（ADR-0005/0006 的投入
   参数承诺实际落空）；
2. **每轮全覆盖 = 负载尖峰**：12 题在第 1/3/7/15/30 天全量脉冲；
3. **完成判定分散**：必修覆盖 + 连续达标 + 最近测验通过三个口径叠加，用户心智是
   "最后考一下，过了就算完成"。

用户产品决策（2026-11-22 拍板，见 change 的 0.x 任务）：澄清步 UI 控件收集
**总时长（周）× 训练次数**，会话由配比控制器分组，**终测单独把关完成**。

## 备选方案

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 保持 ADR-0021 固定五轮 | 零改动 | 参数无家可归、负载尖峰、完成口径分散 | 否（存量保留） |
| SM-2/FSRS 自适应间隔 | 最贴记忆曲线 | 参数黑盒、用户无法预测"哪天完" | 否（FSRS 路径挂到控制器上，见 performance-driven-scheduling D6） |
| **并集 100% + 重叠巩固 + 恒稳控制器 + 终测门** | 用户预测得了"练几次、哪天练、怎么算完"；难度自动回 80%±10% 目标带；纯函数可单测 | 配比表/五星映射首版靠直觉【待校准】 | **采纳** |

## 决策

1. **节奏参数进澄清步 UI 控件**（非对话）：`horizon_days`（1-56 天，UI 以周计）×
   `session_count`（2-6 次），user_input 来源落 goal 快照并进 `missing_fields`；
   提示词第 6/7 条修订——禁的是 **LLM 对话追问**，收集职责移交 UI。
2. **配比模型**：跨会话并集 = 100%（每项至少 1 次，不可协商）；单次占比随次数
   递减、重叠递增（N=2：每次 70%、重叠 40% = 已知巩固 + 错题回炉）【配比表待校准】。
3. **正确率恒稳控制器**：以最近一次会话判分正确率为输入（目标带 80%±10%）动态分配
   重叠池构成——>90% 降已知升错题（镜像外推）、70-90% 维持 20:20、60-70% 改 25:15、
   <60% 改 30:10【外推档待校准】。**分配为纯函数**（相同输入必得相同分配），
   LLM MUST NOT 参与分配或配比决策。
4. **五星"值得复习率"** 定桶内入选顺序：错题 5★ > 回归（先对后错）3★ > 不稳定答对
   2★ > 稳定答对 1★【映射待校准】。
5. **终测完成门**：最后会话后终测（trigger='final'）覆盖全部必修项；通过 → 训练
   completed；不通过 → **追加一轮同规格周期**（已稳定项进已知巩固池），周期小测
   （每 14 天）并存；horizon 用尽时通过追加周期的显式信息提示用户（继续或归档），
   不静默无限延长。
6. **提前练**：允许；提前完成只解锁后续，不改其余会话排期语义（日期由系统在
   horizon 内均匀摊开，保持确定性）。
7. **存量隔离**：`trainings.schedule_mode` 两值——`legacy_v21`（默认，存量零迁移）
   / `session_ratio`（节奏提交即切换）；`generate_plan` 按模式分发。

## 后果

- ADR-0021 的"轮"语义在 legacy 训练上继续成立；新训练的 `plan_items.round_index`
  承载会话序号（周期内 1..N，追加周期顺延）。
- 判分公式 / verdict / 达标 streak 语义**零变化**（graded attempt 是控制器的输入，
  不是它的输出）。
- 连败信号（coach-memory）与 `daily_minutes_target` 偏好是控制器的现成输入；
  回炉/排期 backlog（adaptive-practice-composition / performance-driven-scheduling）
  被本模型吸收或改挂控制器。
