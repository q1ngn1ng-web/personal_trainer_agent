# ADR-0001 LLM 负责语义，规则负责状态迁移

- **状态**：已采纳
- **日期**：2026-09-19
- **关联**：`src/llm/client.py`、`src/services/`、spec `llm-observability`、spec `daily-execution`

## 背景

训练目标的输入是自然语言且通常不完整。"我想学 Redis"没有说明目标等级、周期、应用场景和验收标准，纯表单无法处理这种输入。

但复习日期与训练状态是**状态迁移**，不是文本生成：让 LLM 直接写日期会导致不可复现、无法单测、模型升级后行为漂移，失败时还可能写出非法状态。

## 备选方案

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 全 LLM 决策（连日期一起生成） | 实现快，语义灵活 | 不可复现、不可单测、无法回归、成本高 | 否 |
| 全规则决策（用户填结构化表单） | 完全可测、可复现 | 入口门槛高，无法处理不完整或口语化目标 | 否 |
| **LLM 提议 + 规则执行** | 兼顾语义理解与确定性状态 | 需要 Schema 校验、重试与降级链路 | **采纳** |

## 决策

- LLM 负责：目标澄清、训练类型识别、计划草案生成、评测解释、调整建议
- 规则负责：约束校验、日期计算、资源上限、状态写入与统计
- LLM 输出全部经 JSON Schema 校验：失败重试（带上次错误反馈）→ 静态降级 → 写 `llm_calls` 审计

## 后果与验证

- **代价**：多出一层 Schema / 重试 / 降级的工程量；"建议"与"执行"必须显式分离，不能混在同一个函数里
- **验证方式**：调度与统计为纯函数，可直接单测（`uv run pytest -q`）；`llm_calls` 表留存 prompt 版本、模型、token、耗时、失败原因，支撑回归与成本分析
- **重评估触发条件**：出现规则无法表达的排期约束时（当前所有间隔调整都可用规则表达）
