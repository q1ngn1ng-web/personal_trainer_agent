# ADR-0007 资料检索先用 SQLite FTS5，不上向量库

- **状态**：已采纳
- **日期**：2026-09-19
- **关联**：OpenSpec change `training-source-selection`；触发条件来源 ADR-0002

## 背景

用户上传的资料需要被检索，才能为训练项找到候选原文片段。可选的检索方案跨度很大：
关键词全文检索、向量检索、两者混合。

判断依据不是"哪个更先进"，而是**当前的规模与要解决的问题**：

- 单个训练的资料来源通常是 1-3 份（教材 + 讲义 + 自己的笔记）
- 切片量在数百级
- 要解决的问题是"给定一个知识点，找到对应的原文段落"，而不是"跨海量语料找语义相似的题"

## 备选方案

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| **SQLite FTS5 全文检索** | 零新增依赖；结果可解释、可单测；写入即可查 | 无法命中同义表达与改写 | **采纳** |
| 向量检索（embedding + 向量库） | 语义泛化强，改写也能命中 | 引入模型依赖、阈值校准、缓存与调用成本；需维护重建流程 | 暂不 |
| 混合检索（FTS5 + 向量） | 覆盖率最高 | 是向量检索的超集，代价叠加 | 暂不 |
| 直接把全部切片塞进上下文让 LLM 自己找 | 零实现成本 | 超上下文、成本高、不可控、无法回归 | 否 |

## 决策

1. 使用 SQLite **FTS5** 建立切片全文索引，检索只在本机完成，不产生 LLM 或 embedding 调用。
2. `source_chunks` 记录 `heading_path`，检索结果可带层级路径返回，便于人工核对。
3. **本阶段不引入 embedding 与向量库。**
4. 重评估触发条件（任一满足即重新评估，并新写 ADR 取代本条）：
   - 出现跨多份资料找同类知识点的需求
   - 出现相似题推荐需求
   - 单个训练的切片量超过数千
   - 用真实资料做对照实验后，FTS5 的召回显著不足

## 后果与验证

- **代价**：同义表达与改写问法搜不到；检索质量依赖用户资料的用词
- **代价**：将来引入向量检索时需要补一次全量重建
- **验证方式**：
  - 用 3 份真实资料建库，人工标注若干「知识点 → 应命中的切片」，统计 FTS5 的命中率
  - 该对照实验结果写入 `workspace/evidence/`，作为是否触发重评估的依据
  - **当前尚未实测，标【待验证】**
- **可行性的旁证**：Anki 至今让用户自己设定每日新卡与复习上限、系统只负责间隔调度
  （来源：docs.ankiweb.net/deck-options.html，2026-09-19 抓取）；SuperMemo 的 SM-2 也是纯确定性算法
  （`I(n) = I(n-1) × EF`，EF 下限 1.3，来源：super-memory.com/english/ol/sm2.htm）。
  这两个长期被验证的系统都说明：**确定性方法在合适规模下足够，复杂度应当由真实瓶颈触发。**
